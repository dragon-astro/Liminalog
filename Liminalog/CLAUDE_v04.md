# Liminalog — CLAUDE.md

## プロジェクト概要

**アプリ名:** Liminalog  
**プラットフォーム:** iOS（iPhone専用）  
**言語:** Swift / SwiftUI  
**コンセプト:** タイムトラッカーの記録の煩わしさを、友達との達成スコア競争というゲーム性で解消し、予定を立てる・予定通りに動く・振り返るという習慣を楽しく身につけられるアプリ。  
**一言で言うと:** 24時間の予定を立てて、記録して、友達とスコアで競う。

## コア仕様

### チャプターの記録
- ウィジェットのグリッドボタンをタップ → 即切り替え
- 前のチャプターは自動終了（endTime を現在時刻で記録）
- **1分ルール:** 1分未満のチャプターは誤タップとみなし上書き削除
- グリッドは最大8個表示、使用頻度順に自動並び替え
- 9個以上は「もっと見る」で展開

### チャプターの編集
- タップ → 詳細表示 + 編集画面
- 空白時間帯タップ → 新規チャプター追加
- 長押し → 削除・移動メニュー

### スコア計算
```
スコア = カテゴリ合計時間達成率 × 80% + 時間軸一致率 × 20%
```
- **合計時間達成率（80%）:** カテゴリごとの予定時間に対する実績時間。超過分は切り捨て
- **時間軸一致率（20%）:** 1440分を1分ずつの点として計算。予定と実績が重なった時間が得点。境界は±15分の許容誤差
- 24時間を空白なく予定で埋める前提（自由時間も含む）

### 日付またぎの処理
- **DB:** 分割なし・1レコードで保存（startTime・endTimeをそのまま記録）
- **スコア計算時:** メモリ上で0:00仮想分割して処理（DBには書き込まない）
- **タイムライン表示:** ユーザーの設定した区切り時間に従う
- **ランキング・比較:** 全員0:00〜23:59の固定サイクルで統一

### ストリーク
- 条件: その日のスコアが**60%以上**の日が連続していること
- 60%閾値 = 赤点ラインのイメージ。普段の予定の範囲内で割と簡単に達成できる
- 精度の高い予定を立てるインセンティブとして機能する

### アンロックシステム
- 累計スコアが貯まると着せ替え・アイコンフレーム・スタンプ・アイコンが解放
- 解放スケジュール（約1年で全解放・約26個）:
  - 1〜3ヶ月: 週1個（約12個）
  - 3〜6ヶ月: 2週に1個（約6個）
  - 6〜9ヶ月: 月1〜2個（約5個）
  - 9〜12ヶ月: 月1個（約3個）
- コンテンツは随時追加予定

### カレンダータブの遷移
- 月カレンダー（全画面）→ 日付タップ → デイビュー（全画面）
- デイビューは左右スワイプで前後の日に移動
- 参考UI: Readdle「Calendars」アプリ

### デイビューの構成
```
上部: 終日・時間未指定エリア（iOSカレンダー予定・タイトルとカラーをテキストで表示）
下部: タイムライン（チャプター記録 + カレンダー予定をうっすく表示）
```

### 友達機能（Phase 3）
- CloudKit + CKShare で承認制相互フォロー
- CKSubscription でリアルタイム同期
- 友達タブ上部: 横スクロールランキング（今日・昨日・今週切り替え）
- 友達タブ下部: 友達プロフィールリスト（達成率・ステータス）

### カテゴリマッピング（Phase 3）
- デフォルトカテゴリは自動対応
- カスタムカテゴリは手動マッピング
- 多対一対応あり
- 比較表示時のカラー統一スイッチ

- **スタイル:** カラフル・エネルギッシュ

- **チャプターカラー:** カテゴリごとにカスタマイズ可能
- **アニメーション:** 気持ちいいアニメーション重視・グラフは数字が育っていく演出
- **ターゲット:** 若者向け（18〜22歳）

## 実装上の注意

- **ウィジェットとアプリのデータ共有:** App Groups を使って SwiftData のストアを共有する
- **現在進行中チャプターの判定:** `endTime == nil` で判定
- **1分ルール:** チャプター切り替え時に前のチャプターの経過時間を確認し、1分未満なら削除して上書き
- **グリッドの並び替え:** `usageCount` を記録のたびにインクリメント
- **スコアの仮想分割:** 日付またぎのチャプターはスコア計算時のみメモリ上で0:00分割。DBには書き込まない
- **EventKit の書き込み権限:** カレンダーへの追加・編集には `EKAuthorizationStatus` の確認が必要
- **友達機能（Phase 3）はソロ完結を壊さない:** 友達タブが空でもアプリとして完全に成立する設計を維持する
