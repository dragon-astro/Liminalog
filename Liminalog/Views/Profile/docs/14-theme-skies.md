# 14. テーマ / 解放テーマ（twilight の空）

アプリの配色テーマの世界観・デフォルト2種・解放テーマの設計。
2026-06-01 時点。[13-visual-identity.md](13-visual-identity.md)（ビジュアル）・[09-profile-design.md](09-profile-design.md)（装飾経済）・AI_TASKS §7.3（アンロック）を繋ぐ。

---

## 0. 結論

- テーマ ＝ **「twilight の空（そら）」**。任意の色でなく、**キュレートされた薄明かりのパレット**。どの空も liminal/atmospheric（グラデ・glow）のまま変奏する。
- **デフォルトは2つ明示**：**宵（Dusk・ダーク標準）／ 曙（Daybreak・ライト標準）**。両方とも designed・同品質・視認性保証（手抜きライト禁止）。
- **解放テーマ ＝ 装飾経済の主役**。毎日見る・本当に欲しい・カードに纏ってシェアで自慢になる。「解放されただけ＝だから何」を解決する。
- 名前は **英＝evocative な空名 / 日＝古風な薄明かり語**（暁・宵・曙・黄昏・茜・朧…全部 liminal family）。
- 実装 ＝ **セマンティックトークン**。テーマ追加＝パレット1個の追加（コード書き換えゼロ）。

---

## 1. 世界観：twilight ＝ 薄明かりの空、その核は「黄昏＝誰そ彼」

- 日本語は dawn/dusk の階調に異常に豊かな語彙を持つ（薄明・東雲・黄昏・朧…）＝**liminal を表現するのに世界一向いた言語**。これがブランドの隠れた武器。
- **核ストーリー：黄昏（たそがれ）の語源は「誰そ彼（たそかれ）＝"あれは誰？"」**。夕暮れは暗くて人の顔が見分けられない＝**境界（liminal）の時間**だから。アプリの世界観（予定と実績のあいだ）が、日本語の単語そのものに埋まっている。
- だから全テーマは「**別の薄明かりの空**」であり、ネオン緑やショッキングピンクのような world観破壊色は作らない。空が変わっても、liminal は不変。

---

## 2. デフォルトテーマ（2種・明示）

ライト/ダークは「単一固定」でなく **両対応**（[13] §2.3 改訂）。デフォルトは宵/曙の2つ。**カードもアプリと同じテーマに従う**（カードを特別に固定しない。ブランドは形＝リング/レイアウト/マークで担保、色非依存）。

### 2.1 宵（Dusk）＝ ダーク標準

[13] §2.1 のパレット。深い藍・菫の夜。
| 役割 | hex |
|---|---|
| canvas | `#0D0B16` |
| surface | `#17132A` |
| elevated | `#1F1A38` |
| divider | `#2A2442` |
| text / secondary / tertiary | `#ECE8F5` / `#9A93B5` / `#6E6890` |
| primary（主役） | `#C9A7FF` |
| reward（特別） | `#FFE3A3` |

### 2.2 曙（Daybreak）＝ ライト標準（Claude 指定 hex）

**淡い薔薇・ラベンダーの夜明け。臨床的な純白は使わない**（「春はあけぼの」）。ライトでも liminal を纏う。
| 役割 | hex | 備考 |
|---|---|---|
| canvas | `#F4EEF6` | 淡いラベンダー寄りのオフホワイト（純白不使用） |
| surface | `#FBF6FB` | わずかに持ち上げ |
| elevated | `#FEFAFE` | 影で立体（純白ベタは避ける） |
| divider | `#E6DCEC` | |
| text / secondary / tertiary | `#2A2440` / `#6A6388` / `#9A93B5` | テキストも深い twilight インク（純黒不使用） |
| primary（主役） | `#7C4DD6` | ライト地で contrast を持つ濃い菫（ダークの `#C9A7FF` は明るすぎる） |
| reward（特別） | `#C98A1E` | ライト地で映える濃い琥珀 |
| dawn グラデ | `#FFE3EC` → `#EBDCFA` → `#FFF0CE` | 淡薔薇→ラベンダー→淡金 |

> ⚠️ ライト（曙）は**設計された dawn であること**。システム白に丸投げ＝washed out ＝ブランドが死ぬ（[13] §9 アンチパターン）。primary/reward は**ライトでは濃く**（コントラストが逆向き）＝トークンがモードで解決する理由。

## 2.3 テーマ × モードの解決仕様

**デフォルトだけが dawn/dusk のペア。他テーマは単一の空（モード無視）。**

| 選択テーマ | システムの Light/Dark | 表示 |
|---|---|---|
| **デフォルト（追従）** | 追従 | システムに合わせ 曙（ライト）/ 宵（ダーク）が入れ替わる |
| **デフォルト（固定指定）** | 無視 | 常に 宵 だけ / 常に 曙 だけ（iOS の Auto/Light/Dark と同じ3択） |
| **解放テーマ（茜・朧 等）** | **無視** | そのテーマ固定（1テーマ＝1つの空。モードの概念を持たない） |

理由：茜（夕焼け）・朧（朧月）は**特定の薄明かりの瞬間**。ライト/ダークのペアにすると識別が薄まり工数も倍。**1テーマ＝1つの空**が正解。

**解決ロジック**
```
active パレット = (選択テーマ == デフォルト)
    ? モード解決（システム追従 or 固定: 曙/宵）
    : 選択テーマの固定パレット
```
カード・友達画面・全 View はこの active パレットに従う。

**注意点**
- **アクセシビリティの逃げ道を必ず残す**：ライト必須層（眩しさ・視覚過敏）が暗い解放テーマを選ぶと暗いままだが、**デフォルト（曙/追従）が常にあるので戻れる**。「システム追従の選択肢は常に提供」を保証する（固定テーマは本人の選択）。
- **どのテーマも自己完結で視認性保証**：単一テーマも視認性正規化（[13] §2.5）がその地に対して効く。
- **将来の任意拡張**：人気テーマを後でペア化（光/闇版）もできるが、基本モデルは単一。今は作り込まない。

## 3. 解放テーマ（twilight の空・キュレート）

任意色でなく、**designed な薄明かりの空**を解放で増やす。全テーマ liminal/atmospheric。

| EN（空） | 日本語（古風な光） | パレットの空 |
|---|---|---|
| Dusk（デフォ） | **宵（よい）** | 深い藍・菫の夜 |
| Daybreak（デフォ） | **曙（あけぼの）** | 淡薔薇・ラベンダーの夜明け |
| Twilight | **黄昏（たそがれ）** | 茜と紫が溶ける境界（世界観の象徴テーマ） |
| Aurora | **極光（きょっこう）** | 緑×菫のオーロラ |

## 4. ネーミング原則

- **日本語＝古典的な薄明かり/空の語**（暁・宵・曙・黄昏・茜・朧・群青・月白…）。全部 liminal family。
- **英語＝その空を表す evocative な名**（Dusk/Daybreak/Aurora/Crimson…）。
- **レアな解放テーマほど"渋い"語**（朧・月白・残照）＝知ってる人はニヤッとする＆ステータス。名前自体が"教養と美意識のフレックス"。

---

## 5. 解放条件

- **条件は中立指標**（[12] 原則・連続記録/累計時間/カード○枚シェア等）。「生産的だったら」は NG（ターゲットを罰する）。
- **難しい＝アスピレーショナル＆ステータス**（レアな空をカードに纏う＝憧れ）。ただし廃人専用にしない・段階的に。
- **無料デフォルト（宵＋曙）は最初から美しい**こと。テーマは"おかわり"であって「課金/グラインドするまでダサい」にしない。
- **マネタイズ**：cosmetic で pay-to-win でないため、一部は達成解放・一部は課金が自然（Z世代の着せ替え課金と相性◎）。

---

## 6. 実装（セマンティックトークン）

- 色を `canvas`/`surface`/`text`/`primary`/`reward`… の**意味で参照**し、**トークンがテーマ＆モードで解決**する（hex 直書きをやめる）。
- **テーマ追加＝パレット1個の追加**（全 View 書き換え不要）。dawn/dusk もテーマも同じ機構。
- **視認性正規化（[13] §2.5）は全テーマ共通**。地の色が変わってもコントラスト保証は同じ関数（ただしライト地用の経路が要る＝明度を下げる方向）。
- **カードはテーマに追従**（特別固定しない）。ブランド＝リング/レイアウト/マークで担保。

> Codex への申し送り：現状 `LiminalTheme` は dusk の hex 直書き＋`preferredColorScheme(.dark)` 固定。**dawn 追加・解放テーマのため、セマンティックトークン化（テーマ→トークン解決）へリファクタが必要**（[13] §2.3/§2.4 と整合）。

## 8. 確定 / 未確定

### 確定
- テーマ＝キュレートされた twilight の空（任意色でない）。全テーマ liminal。
- デフォルト2種：宵（Dusk/ダーク）・曙（Daybreak/ライト）。両対応・同品質・視認性保証。
- カードはテーマ追従（特別固定しない）。ブランド＝形で担保。
- 名前：英＝空名 / 日＝古風な薄明かり語。黄昏＝誰そ彼 を核ストーリーに。
- セマンティックトークン化で実装（テーマ追加＝パレット追加）。

### 未確定
- 曙（ライト）パレットの最終 hex（§2.2 は提案）。
- 各解放テーマのパレット具体値・解放条件の閾値。
- 達成解放 / 課金 の配分。
- ライト地用の視認性正規化（明度を下げる経路）の実装詳細。
