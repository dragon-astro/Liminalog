### Codex の内部処理（2026-10-16）

AI_TASKS §8.17 の内部処理を実装。Claude の画面構成は維持する。

- **毎月第○曜日**：`PlanRecurrenceRule.monthlyMode` の `.dayOfMonth` / `.ordinalWeekday`、`monthlyOrdinals` の `.first`〜`.fourth` / `.last`、`monthlyWeekday`（日=1〜土=7、nil=開始日の曜日）を追加。旧JSONは日付方式のまま読み、第4と最終が同日なら1回と数える。予定／一日プリセットは同じ生成処理を通る。**Claudeへの接続点**：月のときだけ方式と序数・曜日を表示し、ルール全体を保持して値を更新する。`MonthlyMode.title` / `MonthlyOrdinal.title` と `summary` が利用可能。2026-10-21 Claudeが選択UIを実装し、CodexがRelease Simulatorで画面・summary・保存の回帰を確認済み（docs/37 §5）。
- **カテゴリのよく使う順**：今日を含む直近90日に作成した、現在存在する予定ブロック数を使う。メイン／メモ共通、実績・外部カレンダー・周期から自動生成されたコピーは除外し、手動で周期登録した元予定は1件と数える。置換で分割された残りは既存モデルの作成日時を持つ各ブロックとして数える（操作回数の記録ではない）。同数は設定順、作成日時、IDの順。ChapterStoreごとのキャッシュを再表示に利用し、保存・日付境界・foreground・外部同期・重複統合で無効化する。取得失敗は空の結果としてキャッシュしない。
- **初回起動**：新規iOS 26.5 Simulatorへの初回install / launchで、修正前Debugも指定どおりカレンダーを開いた。報告症状は今回未再現。別途、共有App Groupに残ったショートカットがfixtureの初期選択を上書きしうる経路を分離した。fixtureでは予約を消費せず、通常起動で1回だけ消費する。待機や再試行で隠す変更はしていない。Release回帰で別途、カレンダーの初期表示モード引数だけが `DEBUG` 限定で、`LIMINALOG_UI_TESTING` を指定しても無視されることを再現。RootTabと同じ条件へ修正し、通常配布Releaseでは引き続き無効にしている。
- **初期スクロール**：ホーム明日の予定読み込み（空→予定あり）で、初期位置7時が0時へ上書きされることを回帰テストで再現。初期位置が実際に反映されるまで保持し、読み込み時も初期時刻を優先する。ユーザーのスクロール開始時には保持を解除。週間は初期7時（スクロール可能範囲内）へ揃え、オフセット位置を日表示と同じ `ScrollPosition` で指定する。非アクティブな隣接ページも共有時刻の変更へ追従させる。遅延・再試行・アニメーション短縮は追加していない。

## 2. 部品の置き換えルール（「トグル→スライダー」の整理）

| 切替の種類 | 使う部品 | 使わない部品 |
|---|---|---|
| 2〜4択の**表示モード**（日/週/月、時間軸/リスト、詳細/控えめ/オフ、メイン予定/予定メモ） | **スライド式セグメント**（全選択肢が見え、つまみが滑る。1タップ） | アイコン＋Menu、押すたびに切り替わる単独ボタン |
| ON/OFF の**設定値**（終日、通知、過去の予定を薄く） | iOS標準スイッチ（現状維持） | セグメント（2択でも意味が「有無」ならスイッチのまま） |
| 多数から**複数選択**（見せるカテゴリ、フィルタ） | カテゴリアイコン付き**チップの複数選択** | 縦に並ぶスイッチ8行 |
| 多数から**単一選択**（予定のカテゴリ） | タイムラインと同じ**カテゴリチップ横列** | 別シートのリスト |
| 頻度の低い詳細（通知の分数、繰り返し規則、公開相手） | 「ラベル左・現在値右・›」の1行→タップで詳細 | ラベルを上に置いた2段行、行→メニュー→シートの3段 |

アイコンの意味も固定する：**⚙=設定画面へ / スライダー=この画面の並び・表示の調整 / ✎=この要素の編集**。

## 3. 提案（優先度つき）

### P1 — 見た目の置き換えで効くもの（データモデル・ジェスチャ所有は変えない）

**P1-1. ~~カレンダーの日/週/月をスライド式セグメントへ~~ → 不採用（2026-10-06）** [05][06]

> 不採用の理由（ユーザーと合意）：日/週/月は「選んだら当分そのまま」の低頻度操作で、2タップの損は毎回の画面の重さに見合わない。表示中のモードは中身（グリッド/列）で一目で分かるため、状態を見せる必要もない。日の時間軸はドロワーのタイムライン入口（35§8）が既にある。タイトルを挟む左右2つずつの対称な配置と、TimeTree と同じ見慣れた形を維持する。
> 判断基準：**表に出すのは「頻繁に使う」か「状態が見えないと困る」もの。どちらでもなければメニューで良い。**
> 代わりに配置を変えずに直すもの：週表示のアイコンが一日プリセットと同じ `calendar.badge.clock` で、同じタブ内で意味が衝突している（`CalendarDisplayMode.systemImage`）。週らしい別のグリフにする。メニューの項目を `Picker` にして、今のモードにチェックが付くようにする。
> プリセット専用行の窮屈さ（35§14）はこの案とは切り離し、別途検討する。

以下は検討時の記録。

```
現在:  [⚙][▦▾]   [2026年10月 ⌄]   [≡][🔍]
       [🔖|📅]                                ← 35§13で「無駄な行」と指摘、§14で未解決
提案:  [⚙]       [2026年10月 ⌄]   [≡][🔍]
       [ 月 | 週 | 日 ]            [🔖|📅]
```

- 切替 2タップ→**1タップ**。現在のモードが文字で読める。
- 「左に2つだけの行」が「表示モード＋プリセット」の意味ある行になり、行を削らずに35§14の未解決点を解消。メニューへ隠す項目はゼロ（§13の差し戻し理由を踏まない）。
- 週・日表示でも同じ行を出す。週表示の「予定プリセット」テキストchip [07] は右側のアイコンペアに統一。
- 対象: `CalendarView.calendarTopBar` / `calendarDisplayModeMenu` / `monthPresetBar`。

**P1-2. 明日ページの「時間軸/リスト」をアイコンのセグメントへ** [04]

- 左上の丸ボタン→メニュー（2択）を `[▤|☰]` の小さなセグメントに。2タップ→**1タップ**、今どちらかが常に見える。
- 対象: `HomeView.tomorrowPlanModeMenu`。

**P1-3. 友達ごとの見え方：セグメント＋チップ** [14]

- 「控えめ ⌃」メニュー → `[詳細 | 控えめ | オフ]` セグメント（組込3種。自作プリセットがある時だけ末尾に「その他…」）。
- 「この相手に見せるもの」スイッチ8行 → カテゴリアイコン付きチップの複数選択（2〜3行に収まる）。「オフ」選択時はチップを無効表示にして、プリセットとカテゴリの関係を画面で示す（今は情報ボタンの説明頼み）。
- 対象: `FriendDetailView` 公開設定カード（`FriendsView.swift` L2395〜）。

**P1-4. 予定編集シートの行を1パターンに揃える** [11][12]

- 「メイン予定 / 予定メモ」セグメントを最上部へ（項目の種類なので、他の設定より先に決める）。
- カテゴリ：ラベル上・青文字・⌄の2段行→別シート、を **カテゴリチップ横列**（タイムラインの作成カテゴリと同じ部品）に。2タップ＋シート→**1タップ**。
- 通知・繰り返し・公開範囲：すべて「ラベル左・現在値右・›」の1行。例「繰り返し　しない ›」「公開範囲　カテゴリの既定（全員）›」。
- 公開範囲：行→メニュー→「公開相手を選ぶ」→シート の3段 → 行→シート の**1段**。シート上部に `[既定 | 全員 | 選ぶ | 非公開]` を置き、メニューの3項目をここに吸収。
- 35§D（現在値を読めるまま軽く）と同じ方向。終日はスイッチのまま。
- 対象: `PlanCreateSheet.body`、`AudiencePickerSheet`。

**P1-5. スクロール時に上部タブが本文と重なる** [02][03]

- ホームの「昨日/今日/明日」の下を本文が素通りし、リング・カード文字と重なって読みにくい。上端に背景色へのフェード（iOS 26 の soft scroll edge）を敷く。
- 対象: `HomeView` の各ページ `NavigationStack`（TabView を safe area 外へ広げている構造は維持）。

**P1-6. 未来日の「一日のまとめ」初期表示** [10]

- 実績タブが初期選択で「未記録」だけが出る。未来日は**予定タブを初期選択**、「0pt 予定待ち」のリングは件数（予定12・重要1）表示へ差し替え。

### P2 — 入口の統一（配置の組み替え）

**P2-1. プリセット入口を全画面で同じアイコンペアに**（35§6でユーザーが挙げた「アイコンだけに統一」の横展開）

| 画面 | 現在 | 提案 |
|---|---|---|
| カレンダー月 | アイコン2つの専用行 | P1-1 の行の右端 `[🔖|📅]` |
| カレンダー週・日 | 「予定プリセット」テキストchip | 同上 |
| ドロワー拡大タイムライン | テキストchip 2つ | カテゴリ列の先頭に `[🔖|📅]`（固定・スクロールしない） |
| ホーム明日 | 「一日プリセット」chip＋右下しおりFAB | 同上。FABは撤去（タイムライン右下の予定を隠さない） |

2つを直接押せる状態は維持（35§13のユーザー判断）。

**P2-2. 設定の入口を整理** [01][15][16][17]

- プロフィール右上 `≡` → `⚙`（ハンバーガーはナビドロワーを連想させる。中身はアプリ設定）。
- ホーム今日の右上スライダー（カテゴリ管理）→ カテゴリグリッド見出し「平日 ⇆ …… ⌃」に `✎` を追加して移す。グリッドの編集はグリッドの横で。右上は空ける。
- 統計のスライダー（カード並べ替え）、カレンダーの⚙（表示設定）は役割がルールどおりなので維持。

**P2-3. タイムラインの初期表示位置**

- ホーム明日・カレンダー週が 0:00 から表示され、睡眠ブロックが画面を占めていた [04][07]（拡大タイムラインは 8:00 から [09]）。ホーム明日は `visibleHour = 7` を意図しているため、ページ型 TabView 内での初回スクロール適用漏れの可能性。**実機 Release で再現確認してから**修正。目標は「起床後の最初の予定」または「現在時刻の1時間前」。

### P3 — 構造（大きめ・要検討）

**P3-1. 「1日を組む」画面の共通ツールバー**

3か所のタイムラインの上部を同一仕様にする：`[戻る/表示切替] [日付] [+]` ＋ `[🔖|📅] | カテゴリチップ…`。中身の `EditablePlanTimelineView` は既に共通なので、外枠だけ揃える。

**P3-2. ドロワー拡大をシートの重ねでなく「同じシートが伸びる」へ**

- 現在：ドロワー（medium）→ タイムラインアイコン → 別の large シート。
- 案：ドロワーを large へ引き上げる／アイコンを押すと、同じシートの中身がタイムラインへ切り替わる。戻る＝引き下げ。35§3A「同じ日付の作業が広がったように見せる」の実装案。
- ドラッグ・スクロールの所有関係に触れるため、P1/P2 の後に試作で比較する。

**P3-3. 公開設定の考え方を画面に出す**

入口が4か所（設定＞友達への見え方・友達セット／友達詳細／カテゴリ編集／予定編集）あり、関係が説明文頼み。「既定＝カテゴリ」「例外＝友達ごと」「上書き＝予定ごと」の3層を、各画面で同じ言葉の現在値1行と、同じチップ部品で表す。設定＞友達への見え方をハブにする。
