## Item A: 友達タブ pull-to-refresh

- **現状**：手動更新は `FriendsView` 内のボタンから `refreshCloudRequests(trigger: .manual)`。スロットルは `CloudFriendLocalStatePolicy`（手動トリガーは即時、自動は抑制）。
- **方針**：友達一覧のスクロールに `.refreshable` を追加。中身は「申請リフレッシュ（manualトリガー）＋共有スナップショットの受信側リフレッシュ」を await で束ね、完了までインジケータを保持。実行中の再スワイプは多重実行させない。
- **受け入れ基準**：
  - 下スワイプ→完了で、新着申請と友達の共有データが反映される。
  - 連続スワイプで CloudKit リクエストが多重発行されない（policyのユニットテストで固定）。
  - 既存の自動リフレッシュ抑制（失敗直後120秒等）を壊さない。

```text
[Codex goal — Item A]
FriendsView に pull-to-refresh を追加する。
現状: 手動更新は refreshCloudRequests(trigger: .manual)（FriendsView:259付近）、スロットルは CloudFriendLocalStatePolicy（手動=即時）。
やること: 一覧スクロールへ .refreshable を追加し、申請リフレッシュと共有データの受信側リフレッシュを await で束ねる。実行中の再入をガードし、多重発行しないことを CloudFriendLocalStatePolicy 側のテストに追加して固定する。
制約: 自動リフレッシュの既存抑制ロジックは変更しない。UI文言追加は最小限。
検証: 対象ユニットテスト、iPhone 16/13 実機で下スワイプ→反映を確認、Release build。AI_TASKS §8.13-A にチェックと完了ログ。
```

## Item B: タイムラインのカテゴリ下地 + その場カテゴリ追加

- **現状**：`Views/Home/TimelineView.swift` のカテゴリ表示（チップ/バー）が半透明で、背後の canvasGradient が透けて視認性が落ちる。
- **方針**：
  1. チップ/バーの背後に不透明寄りの下地（`LiminalTheme.surface` / `elevated` ベース）を敷き、グラデの透けを止める。宵/曙の両テーマでスクショ確認。
  2. タイムライン上のカテゴリ選択UIに「＋ 新しいカテゴリ」を追加。既存の `CategoryEditSheet` を再利用してその場で作成→作成したカテゴリを即選択状態にする。
- **受け入れ基準**：
  - 両テーマで文字・カテゴリ色が沈まない（スクショ添付）。
  - タイムラインから離れずに 新規作成→選択→記録開始 が1フローで完了。
  - カテゴリ上限まわりの現行仕様（作成可否の制御）は `CategoryEditSheet` / `CategoryStore` の既存挙動に従い、新ルールを勝手に足さない。

## Item C: タイムラインの拡大（ズーム）

- **方針**：デイタイムラインの時間軸スケール（1時間あたりの高さ）を可変にする。ピンチ（MagnifyGesture）で段階ズーム（例: 0.75x / 1x / 1.5x / 2x にスナップ）＋最後のスケールを永続化。拡大中もスクロール位置のアンカー（画面中央の時刻）を維持する。
- **受け入れ基準**：
  - ピンチで拡大縮小でき、指を離すと最寄りの段階にスナップする。
  - ズーム時に表示中の時刻帯が飛ばない（中央アンカー維持）。
  - **Release実機でスクロール/ズームが滑らか**（§3.5.1。Debugの体感で最適化しない）。
  - スケールはアプリ再起動後も保持。

```text
[Codex goal — Item C]
デイタイムライン（TimelineView）の時間軸ズームを実装する。
やること: 1時間あたりの高さをスケール可変にし、MagnifyGesture で 0.75/1/1.5/2x へスナップ。ズーム中は画面中央の時刻をアンカーとしてスクロール位置を維持。最終スケールを UserDefaults に永続化。
制約: レイアウト計算の変更は表示モデル側に寄せ、ビュー本体の肥大を避ける。パフォーマンス判断は必ずRelease実機（AI_TASKS §3.5.1）。
検証: Release実機（iPhone 13 含む）でズーム/スクロールの滑らかさ確認、スケール永続化の再起動確認、既存タイムラインテスト、Release build。AI_TASKS §8.13-C にチェックと完了ログ。
```

## Item D: カテゴリアイコンの「表/裏」ライブラリ

- **現状**：`Views/Settings/CategoryEditSheet.swift` にアイコン候補がハードコード配列（symbol+label・数十件）で直置き。
- **方針**：
  1. **裏（ライブラリ）**：SF Symbols からジャンル別（学習・仕事・運動・生活・趣味・健康・移動・休息…）に整理した大きめの静的カタログをコード定義（数百件規模可。存在しないシンボル名を混ぜないこと）。
  2. **表（クイック選択）**：ユーザーがピン留めした「よく使う」枠。ピン状態を永続化（軽量なので UserDefaults で可。モデル変更なし）。
  3. **ピッカーUI**：表セクション → ジャンル別セクション の順で表示＋検索バー（ラベル・シンボル名でフィルタ）。各アイコンはピン留め/解除できる（長押しメニュー or ピンボタン）。ShipSwift の SearchBar/グリッド系レシピは参考まで（実装は自前・トークン準拠）。
- **受け入れ基準**：
  - 既存カテゴリの保存済み `icon` 文字列は無変更で表示互換（カタログに無いシンボルでも表示だけは通す）。
  - 検索でラベル/シンボル名の両方がヒット。
  - 表の並びと内容が再起動後も保持。
  - シート内で完結（別画面遷移を増やさない）。

```text
[Codex goal — Item D]
カテゴリアイコン選択を「表（よく使う・ピン留め）/ 裏（ジャンル別の大規模ライブラリ）」構成に再設計する。
現状: CategoryEditSheet にハードコード配列（symbol+label）。
やること: (1) SF Symbols をジャンル別に整理した静的カタログ（実在シンボルのみ・数百件規模）をコード定義に切り出す。(2) ピン留め＝「表」枠を UserDefaults で永続化。(3) ピッカーを 表→ジャンル別＋検索 の構成にし、ピン留め/解除をシート内で完結させる。
制約: 既存カテゴリの icon 文字列は互換維持（未収載シンボルも表示は通す）。色・スタイルは LiminalTheme トークン。SwiftData モデルは変更しない。
検証: 実在しないシンボル名が無いことの検査（カタログ全件を UIImage(systemName:) で回すユニットテスト）、ピン永続化テスト、両テーマスクショ、Release build。AI_TASKS §8.13-D にチェックと完了ログ。
```

## Item E: リスト並び替えの横展開

- **現状**：`CategorySettingsView` には `.onMove` 実装済み（`Category.sortOrder` / `CategorySet.sortOrder`）。他のリスト管理画面には未展開。
- **方針**：リスト形式の管理画面を棚卸しし、同じ並び替えパターンを展開する。対象候補：カテゴリセット一覧、友達セット（`FriendSetSettingsView`）、公開プリセット（`VisibilityPresetSettingsView`）、予定プリセット（§8.12/docs/22 と実装が重なる場合はそちらを優先し二重実装しない）。`sortOrder` の採番正規化（0..n-1 詰め直し）を共通ユーティリティに切り出す。
- **受け入れ基準**：
  - 各対象リストでドラッグ並び替えができ、再起動後も順序が保持される。
  - CloudKit 同期対象モデルは sortOrder 変更が同期に乗ることを確認（既存の同期経路で自然に流れることの確認でよい）。
  - built-in/seed 行の特別扱い（あれば）を壊さない。

```text
[Codex goal — Item E]
リスト並び替えを管理画面へ横展開する。
現状: CategorySettingsView に .onMove 前例あり（sortOrder 採番）。

制約: built-in seed 行の特別扱いを保持。CloudKit同期対象は順序変更が同期に乗ることを確認。
検証: 対象画面ごとの並び替え→再起動保持、ユーティリティのユニットテスト、Release build。AI_TASKS §8.13-E にチェックと完了ログ。
```

## Item G: タブ常駐バッジの廃止（採用済み・X1）

```text
[Codex goal — Item G タブ常駐バッジ廃止]
```
