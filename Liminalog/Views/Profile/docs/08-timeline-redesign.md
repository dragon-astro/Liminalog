# 08. タイムライン UI 再設計 v2

ユーザー提示の「Liminalog — タイムラインUI仕様 v1.0」を受け、2026-05-25 時点で記録・表示まわりを再設計する。
このドキュメントは [05-screen-flow.md](05-screen-flow.md) のタイムライン部分と、旧 `08. タイムライン UX 再設計 v1` を上書きする。

---

## 0. 結論

縦方向に時間幅を表す従来のタイムライン形式は廃止し、以下を新しい主 UI とする。

1. **24時間バー**
   - 0:00 から 24:00 までの絶対時間位置を横幅で表す
   - 予定と実績を 2 段で常時表示する
   - 正確な時間の長さ・空き・偏りを俯瞰する

2. **固定高さカードリスト**
   - 予定タブ / 実績タブで切り替える
   - 各 Chapter / PlanBlock は時間の長さに関係なく同じ高さのカードで表示する
   - 開始終了はカード左外の時刻レールに出し、カード内はカテゴリ名・状態インジケータ・補助情報に絞る

現行タブは **実績 / 予定の 2 タブのみ** とする。
旧案の **実績 / 比較 / 予定**、または **予定 / 実績 / 両方** の 3 タブ構成は撤回済み。
比較はタブではなく、常時表示の 24時間バー 2 段で行う。

設計の役割分担は明確に分ける。

| UI | 役割 | 時間の正確さ | 読みやすさ |
|---|---|---:|---:|
| 24時間バー | 1日の俯瞰・比較・位置把握 | 高い | 低め |
| カードリスト | 内容確認・編集・操作 | 中 | 高い |

## 1. 旧方針からの変更点

### 廃止するもの

- 縦方向の 24 時間タイムラインを主 UI にする方針
- 実績 / 比較 / 予定の 3 モード切替
- 比較モードの左右分割レーン
- ブロック高さで時間の長さを表す表現
- 重なり回避のための横分割カラム計算を主 UI に持ち込む方針

### 継続するもの

- カテゴリ切替では Chapter を削除しない
- 予定と実績は別データとして扱う
- 色だけに頼らず、アイコンとテキストを併記する
- タップで編集・詳細へ進める
- 当日の短時間記録はデータとして残す（誤タップでも今日は手動削除に委ねる）

### 理由

縦方向タイムラインは、時間の長さを視覚的に表せる一方で、短時間記録・連続切替・長時間記録が混ざると表示密度が破綻しやすい。
今回の設計では、正確な時間幅は 24時間バーに任せ、カードリストは読みやすさと操作性に集中させる。

│ 予定 [██░░░░████░░██████░░░░░░] │
│ 実績 [██░░░████░░░████████░░░░] │

├─────────────────────────────────┤
│ 今日のタイムライン               │
├─────────────────────────────────┤
│ [実績] [予定]  タブ切り替え      │
├─────────────────────────────────┤
│ カードリスト（画面全体でスクロール）│
│ 09:00 ┃ [icon] 勉強        2時間 │

│ 11:00 ┃ [icon] 休憩        15分  │

### 表示順

上から以下の順に表示する。

- ナビゲーションバー中央の日付表示
- 24時間バー
- タイムライン見出し
- 実績 / 予定の Segmented Control

24時間バーはタイムラインの見出しではなく、1日の俯瞰 UI として独立して扱う。
カードリスト自体には内部スクロールを持たせず、ホーム画面全体のスクロールに統合する。
旧縦タイムライン用の「現在時刻へ自動スクロール」は行わない。カード式では `CurrentChapterCard` と active ハイライトで現在の記録を示す。

### タブ

| タブ | 表示対象 | 用途 |
|---|---|---|
| 実績 | `Chapter` と実績の空白時間 | 実際の記録を確認・編集する |
| 予定 | `PlanBlock` と予定の空白時間 | 今日の計画を確認・追加する |

表示順は **実績 / 予定** とする。
`比較` / `両方` タブは作らない。
初期選択は **実績** とし、最後に選択したタブを `@AppStorage` で保存する。

24時間バーはタブに関係なく、常に予定・実績の両方を表示する。

## 3. データ保存仕様

### Chapter

カテゴリ切替時の保存仕様は現行の安全方針を継続する。

1. 記録中の Chapter があれば `endTime = now` で終了する
2. 押されたカテゴリで新しい Chapter を作成する
3. カテゴリ切替・手動停止では 1 分未満でも自動削除しない
4. 自動リザレクト・自動統合はしない
5. 手動停止時も短時間記録を削除しない

記録の正確性を最優先するため、見た目を整える目的で Chapter を削除・結合しない。
短時間記録や同分内の切替が見づらい場合は、表示側でミニマルに扱う。

#### 日付またぎと重複の原則

- Chapter は日付またぎを許可する
- DB 上では日付で分割せず、1つの活動を1つの Chapter として保存する
- 表示・スコア・24時間バーでは対象日の 0:00-24:00 にクリップする
- 実績 Chapter 同士の重複は原則禁止する
- 通常のカテゴリ切替では active Chapter を最大1件に保ち、重複を作らない
- 手動追加・編集で既存 Chapter と重なる場合は、保存前に警告し、まずは保存をブロックする
- 2026-05-28 実装: `ChapterStore.canCreateChapter` / `saveChapter` が重複を検出し、`ChapterCreateSheet` / `ChapterEditSheet` は保存不可理由を表示して閉じない
- 将来的に必要になれば、編集UXとして「重なった部分を置き換える」を追加検討する
- 自動で勝手にマージ・削除・切り詰めは行わない

#### 前日以前の 1 分未満 Chapter のガベージコレクション

誤タップ等で蓄積した短時間ゴミデータを定期的に除去する。

- **対象**: `endTime != nil`（完了済み）かつ `startTime < 今日の 0:00` かつ `endTime - startTime < 60 秒`
- **タイミング**: アプリ起動時（`RootTabView.task` 内）に `pruneShortChapters()` を呼ぶ
- **当日のデータは対象外**: 誤タップに気づいて自分で消せるよう、今日の 1 分未満は残す
- **スコアへの影響**: `ScoreCalculator` でも完了済み 1 分未満 Chapter を除外して計算する（`endTime != nil && duration < 60` はスコア対象外）

### PlanBlock

予定タブでは、対象日の `PlanBlock` を開始時刻順に表示する。
スコアの公平性を守るため、当日スコアは「前日までに組んだ予定」と「当日の実績」を比較する。

- 予定の新規追加・内容/カテゴリ/時間変更・削除は明日以降だけ許可する
- 今日以前の時間つき予定は内容・カテゴリ・時間を固定する
- 今日以前の時間つき予定でも、重要フラグ・メモ・公開設定は後から編集できる
- 時間未指定の重要予定 (`isAllDay == true`) はスコア計算から除外されるため、過去日・今日・複数日またぎでも追加・編集・削除できる
- 時間未指定の重要予定を時間つき予定へ変換する場合は、スコア対象になるため明日以降の日付でなければ保存できない
- 実装上は `PlanBlock.createdAt` ではなく、対象予定の `startTime` が今日以前かどうかで編集ロックを判定する

### 編集ロック

スコアが友達比較・ストリーク・アンロックに使われるため、あとから時間軸を都合よく変えられないようにする。

| 対象 | 今日 | 前日以前 | 明日以降 |
|---|---|---|---|
| 時間つき予定 | 時間/カテゴリ/内容はロック、重要フラグ/メモ/公開設定のみ可 | 時間/カテゴリ/内容はロック、重要フラグ/メモ/公開設定のみ可 | 新規追加・編集・削除可 |
| 時間未指定の重要予定 | 新規追加・編集・削除可 | 新規追加・編集・削除可 | 新規追加・編集・削除可 |
| 実績 | 時間/カテゴリ/削除も可 | 時間/カテゴリ/削除はロック、メモ/気分/場所/公開設定のみ可 | 原則作成しない |

実績のロック判定は「開始日」ではなく「今日の 0:00-24:00 に重なっているか」で見る。日付またぎ Chapter は DB 分割しないため、開始が前日でも今日に重なっている間は今日の実績として時間/カテゴリ/削除を編集できる。今日に一切重ならない実績は前日以前としてロックする。

前日以前の実績時間を修正できる例外を将来入れる場合は、変更履歴が後から分かる監査表示を必須にする。現行実装では例外を入れず、時間とカテゴリをロックする。

### 日付またぎ

24時間バーとカードリストは、対象日の **0:00-24:00 固定** にクリップした表示を行う。
「1日の始まり時間」をユーザーが変更する機能は、コア機能の解釈を揺らすため現行スコープから外す。
将来的に数年単位の大きなアップデートで再検討するが、当面はスコア・ランキング・共有・タイムラインのすべてで 0:00-24:00 を共通の1日とする。

- 前日から継続している記録: 0:00 開始として表示する
- 翌日に続く記録: 24:00 終了として表示する
- 実データの `startTime` / `endTime` は変更しない

## 4. 24時間バー仕様

### 基本

- 左端は 0:00、右端は 24:00
- 横位置と幅は実時間に比例させる
- 予定行と実績行の 2 段を常時表示する
- 行ラベルは `予定` / `実績`
- 目盛りは 0, 3, 6, 9, 12, 15, 18, 21, 24 を表示する
- 画面幅が狭い場合、目盛りラベルは間引くが、位置計算は変えない

### セグメント表示

各 Chapter / PlanBlock は `TimelineBarSegment` として描画する。

| 条件 | 表示 |
|---|---|
| 15分未満 | カテゴリカラーのみ |
| 15分以上かつ表示幅が十分 | カテゴリカラー + アイコン |
| 表示幅が狭い | アイコンを省略し、カラーのみ |
| active Chapter | 右端を現在時刻まで伸ばし、記録中インジケータを付ける |

同じカテゴリが飛び飛びに現れる場合も、結合せず別セグメントとして表示する。

### 正確さとタップしやすさ

バー本体の幅は実時間に忠実にする。
ただし短いセグメントはタップしづらいため、見た目の幅は変えずに透明な hit area を広げる。

### インタラクション

バーセグメントをタップしたとき:

1. カテゴリ名、開始終了、経過時間を含む quick detail を表示する
2. 対応カードを一時的にハイライトする

カードリストはホーム画面全体のスクロールに統合するため、`ScrollViewReader.scrollTo` による内部ジャンプは使わない。

バーの空白部分をタップしたとき:

- 追加操作は行わない
- バーは俯瞰・確認専用とし、新規作成は行わない
- 新規予定・新規チャプター作成は画面上部の `+`、カテゴリ記録導線、または空白カードのタップへ集約する

## 5. カードリスト仕様

### 共通カード

カードはすべて同じ高さにする。
時間の長さをカード高さで表現しない。

```text
09:00 ┃ ┌──────────────────────────┐
      ┃ │ [icon] カテゴリ名 予定通り 2時間 │
11:00 ┃ │ メモなど                  │
      ┃ └──────────────────────────┘
```

必須表示:

- カード左外の開始時刻・終了時刻
- カテゴリアイコン
- カテゴリ名
- 状態インジケータ（必要な場合のみ）
- 経過時間（カード右側）

カード左外には、乗り換えアプリのような時刻レールを表示する。
カード左端にはカテゴリカラーの細いバーを表示してもよいが、これはカテゴリ識別用であり時間の長さは表さない。
カード右側には、そのカテゴリを何分/何時間やったかを表示する。
開始・終了時刻は左外の時刻レールへ任せ、カード内には時刻範囲を重複表示しない。

### 固定高さと追加情報

メモ、気分、写真、場所名はカード内の補助行に表示する。
カード高さは変えず、表示しきれない情報は `+N` やアイコンで要約し、詳細画面で全文を見せる。

例:

- `note` がある: `text.bubble` + 先頭数文字
- `mood` がある: 気分アイコンまたは短いラベル
- `photo` がある: `photo` アイコン、サムネイルは詳細画面優先
- `locationName` がある: `location` + 場所名短縮

### 実績カード

- `Chapter` から生成する
- 記録中は文字バッジを出さず、カード枠・背景・時刻レールのハイライトで表す
- `実績` ラベルは表示しない。タブで文脈が分かるため、カード内には出さない
- 日付またぎの `継続` バッジは通常カードには出さない。必要なら詳細画面・アクセシビリティで扱う
- 予定と同じカテゴリ・重なる時間帯で記録している場合は、カテゴリ名の横に `予定通り` インジケータを小さく表示する
- 当日の 1 分未満 Chapter も削除せず、表示側で最小限に扱う（`1分未満` と表示）
- 前日以前の完了済み 1 分未満 Chapter はアプリ起動時に自動削除される（§3 参照）

### 予定カード

- `PlanBlock` から生成する
- `calendar` アイコンを補助的に表示する
- 実績カードより少し軽い背景にする
- 開始前 / 進行中 / 終了済みの状態をテキストで分かるようにする

### 空白カード

イベント同士の隙間は `空白カード` として表示できる。

| タブ | 空白カードの意味 | タップ |
|---|---|---|
| 予定 | 予定がない時間 | タップで `PlanCreateSheet` を開く（開始時刻をギャップ先頭に設定） |
| 実績 | 記録がない時間 | タップで `ChapterCreateSheet` を開く（原則ギャップ先頭を開始時刻に設定。現在時刻に接するギャップや上部 `+` からの追加では、開始=終了にならないよう現在時刻から編集可能な範囲へ補正する） |

空白カードは通常カードより控えめな表示にし、`未予定` / `未記録` と時間範囲を表示する。
タップ可能であることを示す `plus.circle` アイコンを右端に表示する。
短すぎる空白（5分未満）はカード化しない。

## 6. 表示モデル

TimelineView のデータ取得は SwiftData `@Query` を使う。
ただし `Chapter.endTime` は optional なので、`endTime == nil || endTime > dayStart` のような日付交差判定を `#Predicate` に直接書かない。
DB からは `startTime` 順に広く取得し、`endTime ?? now` を使った対象日フィルタは Swift 側で行う。

理由:

- 記録中 Chapter は `endTime == nil`
- カテゴリ切替直後の直前 Chapter は `endTime != nil`
- どちらもタイムラインに必要だが、optional を含む複合 predicate で取りこぼすと、削除していないのに UI 上は消えたように見える
- `try? modelContext.fetch(...)` でエラーが潰れると原因が見えづらい

UI は `@Query` で取得した `Chapter` / `PlanBlock` をそのまま描画せず、表示用モデルに変換してから描画する。

```swift
enum TimelineEntryKind {
    case plan
    case actual
    case gap
}

struct TimelineEntry: Identifiable {
    let id: String
    let kind: TimelineEntryKind
    let sourceID: UUID?
    let start: Date
    let end: Date
    let clippedStart: Date
    let clippedEnd: Date
    let categoryName: String
    let categoryIconName: String
    let categoryColorHex: String
    let isActive: Bool
    let metadata: TimelineEntryMetadata
}
```

24時間バーとカードリストは同じ `TimelineEntry` から生成する。
これにより、バーをタップした時に対応カードへ確実にジャンプできる。

### ID ルール

- Chapter: `actual:<chapter.id>`
- PlanBlock: `plan:<plan.id>`
- 空白カード: `gap:<kind>:<startISO>-<endISO>`

## 8. 状態管理

### AppStorage

旧 `timelineDisplayMode` は 3 モード前提なので廃止または移行する。
新しいキーは以下とする。

```swift
@AppStorage("timelineSelectedTab") private var selectedTabRawValue = TimelineTab.actual.rawValue
```

`timelineDisplayMode` が残っていても新 UI では参照しない。
移行する場合は以下のように扱う。

- `actual` -> `actual`
- `plans` -> `plan`
- `comparison` -> `actual`

### 更新タイミング

- `store.revision` 変更
- `date` 変更
- active Chapter がある場合の timer tick
- PlanBlock 追加・編集・削除

## 9. 実装優先順位

1. **表示モデル導入**
   - `TimelineEntry` / `TimelineEntryBuilder`
   - 日付クリップ
   - gap 生成

2. **24時間バー**
   - 予定 / 実績 2 段
   - 時間比例配置
   - 目盛り
   - active 更新

3. **カードリスト**
   - 予定 / 実績タブ
   - 固定高さカード
   - 空白カード
   - 詳細・編集導線

4. **バーとカードの連動**
   - quick detail
   - カード一時ハイライト
   - 内部 scrollTo は使わない

5. **旧タイムラインの撤去**
   - 比較モード削除
   - 左右分割レーン削除
   - 縦方向の時間比例ブロック削除

## 10. テスト観点

- カテゴリ切替で Chapter が削除されない
- A→B→C の短時間切替でも A/B/C が別 Chapter として残る
- 1分未満の Chapter も実績カードとして表示される
- 日付またぎ Chapter は DB では1件のまま、表示だけ対象日の 0:00-24:00 にクリップされる
- 実績 Chapter 同士の重複は手動追加・編集時に検出され、保存前にブロックされる
- 全カードの高さが揃う
- 24時間バーの位置と幅が 0:00-24:00 に対して正しく比例する
- 15分未満セグメントではアイコンが省略される
- 15分以上でも表示幅が狭い場合はアイコンが省略され、テキスト衝突しない
- 同じカテゴリの飛び飛び記録が結合されず別セグメントになる
- 予定タブでは PlanBlock と予定空白カードだけが表示される
- 実績タブでは Chapter と実績空白カードだけが表示される
- タブ切替後も 24時間バーは予定・実績の 2 段を維持する
- バーセグメントタップで quick detail が表示され、対応カードがハイライトされる
- バー空白タップでは追加画面が開かない（バーは俯瞰専用）
- 空白カード（未記録/未予定）タップで対応するシートが開き、ギャップ先頭時刻がセットされる
- active Chapter のバー幅とカード経過時間が timer で更新される
- 日付またぎ記録が対象日の範囲にクリップされる

## 11. Claude/Codex への注意

- 旧 `実績 / 比較 / 予定` の 3 モード UI は新仕様では使わない
- 旧 `予定 / 実績 / 両方` の 3 タブ案も新仕様では使わない
- 比較はタブではなく、常時表示の 24時間バーで行う
- カード高さに時間の長さを反映しない
- 時間の長さを正確に見せるのは 24時間バーだけにする
- カテゴリ切替・手動停止では短時間記録を削除・統合しない。見た目を整える目的での削除は行わない
- 前日以前の完了済み 1 分未満 Chapter の自動削除は `pruneShortChapters()` のみ。それ以外のタイミングで短時間 Chapter を消してはいけない
- バーをタップして新規追加を開いてはいけない（バーは俯瞰専用）。追加は空白カードタップ・画面上部 `+`・カテゴリ記録導線から行う
- 色だけで意味が分かる UI にしない。アイコンとカテゴリ名を必ず併記する
- バーの見た目幅をタップしやすさのために歪めない。hit area だけ広げる
- 旧ログに 3 タブ・左右分割・scrollTo・空白タップ追加が残っていても、それらは v1 履歴または撤回済みの記録として扱う
