# 10. 今日タブ / 3ページ構成（昨日・今日・明日）

「前日の振り返り・今日の記録・翌日の予定を、ほかの過去未来とは分離して一繋がりの体験にしたい」という要求を受け、2026-05-29 時点で今日タブの情報構造を確定する。
このドキュメントは [05-screen-flow.md](05-screen-flow.md) の今日まわり、[08-timeline-redesign.md](08-timeline-redesign.md)（今日ページの中身）の親構造として位置づける。

---

## 0. 結論

今日タブは、上部のテキストタブで切り替える **3ページ固定構成** とする。

| ページ | 役割 | 時間軸 | 主な中身 |
|---|---|---|---|
| 昨日 | **振り返り（内省）** | 確定した過去 | スコア、簡単なインサイト、統計サマリ |
| 今日 | **記録** | 進行中の現在 | 24時間バー + カードリスト（08で確定済み） |
| 明日 | **予定** | これからの未来 | 予定ビュー（カレンダー日付詳細を再利用）+ 行動を促す仕掛け |

- 起点は常に **今日**。タブを離れて戻ったら必ず今日ページに戻る。
- 上部テキストタブ（昨日｜今日｜明日）で切替。横スワイプ切替も許容。
- **日付ストリップ（日送りスクラブ）は不採用**。理由は §2。

---

## 1. なぜ「今日タブ」に3つをまとめるのか

昨日・今日・明日は、ユーザーの頭の中で **「今この瞬間の地続きの前後」** として一繋がりに処理される。
「昨日こうだった → 今日これをやる → そういえば明日これがある」という連続した思考をそのままなぞる場所が要る。

これは「任意の過去・未来へランダムアクセスする」カレンダータブとは脳の使い方が別物である。

- **今日タブ** = 今を起点にした、昨日・今日・明日の3日だけに閉じた地続きの体験
- **カレンダータブ** = 月グリッドで遠い日へ一気に飛ぶランダムアクセス

3日だけに閉じることで、カレンダーとの境界が自動的に綺麗になる（**3日 vs それ以外**）。

---

## 2. なぜ3ページ固定で、日付ストリップを採らないのか

検討の過程で「日付を横にスクラブして任意の日へ滑らかに移動する」案が出たが、撤回した。

理由は **ページの役割を昨日=振り返り / 今日=記録 / 明日=予定と分けている** から。
日をコロコロ動かせる形式は「どの日も中身が同じ」であることが前提になる。役割を3種類に分ける設計とは原理的に両立しない。

- 役割を分ける → **ページは3枚で固定** が必然
- 日送りストリップ → 各ページの中身を統一する必要があり、振り返り/記録/予定の分離が壊れる

また、日付ストリップは「どこまでスワイプすれば良いのか」が曖昧でノイズになる。
近所（昨日・今日・明日）は今日タブ、遠出（それ以外の日）はカレンダー、という役割分担を明確にするためにも、今日タブは3日に閉じる。

---

## 3. 昨日ページに持たせたい意味（このページの核心）

昨日ページは **「自分の1日を統括的に振り返り、内省する場所」** とする。主語は常に自分。

### 3.1 ここに置く目的

- **1日を締める区切りを作る**：記録しっぱなしで終わらせず、「昨日はどうだったか」を受け取る面を用意する。記録の動機（めんどくささに勝つ理由）を、振り返りの満足感で補強する。
- **記録が「データの蓄積」から「意味のある1日」に変わる**：バーやカードは事実の羅列だが、昨日ページはそれをスコア・インサイト・統計として **解釈** して返す。記録した甲斐があったと感じさせる。
- **習慣維持のモチベーション**：「昨日はこうだった」を毎朝受け取れることが、今日も記録する理由になる。

### 3.2 載せる要素と、それぞれの意図

| 要素 | 意図 | 主従 |
|---|---|---|
| スコア | 昨日1日を1つの指標で受け取る。良し悪しの一次情報 | 主 |
| 簡単なインサイト | 「いつもより○○が多い/少ない」など、事実の解釈を1〜数行で返す | 主 |
| 統計サマリ | カテゴリ別時間など、振り返りに必要な最小限の集計 | 従 |
| ランキング（検討中） | 友達との比較。**入れるとしても従**。§3.3 参照 | 検討中 |

### 3.3 ランキングの扱い（保留・慎重に）

ランキングは **競争・対社会** の軸であり、振り返り（自分の1日を内省する）とは脳の使い方が違う。
昨日ページに対等に混ぜると「内省したいのに順位が目に入る」ノイズになりうる。

方針（暫定）：

- 昨日ページの主役は **自分のスコア・インサイト・統計** に保つ
- ランキングは入れても **末尾に1ブロック**、または友達タブへの「友達と比べる →」リンク1つに留める
- 「振り返りを統括的に」の主語を **自分** から逸らさない

### 3.4 自動日記（DayDigest）との関係（保留）

文章ベースの自動日記（DayDigest）を昨日ページに載せるか、プロフィールへ投稿として溜める別物にするかは **未確定**。
体験のイメージが固まっていないため、一旦保留とする（Codex にも検討を依頼）。

- 候補1：昨日ページ = スコア/統計の振り返り。DayDigest は別物としてプロフィールに溜まる
- 候補2：昨日ページ = スコア/統計 + DayDigest の文章も載せる

決まり次第このセクションを更新する。

### 3.5 昨日ページの編集ポリシー

- 昨日の Chapter は **編集ロック済み**（08・編集ロックモデルに準拠）。
- 昨日ページは「確定したものを読む」体験に徹する。**編集導線は持たせない**。
- 振り返りから過去を書き換えられないことが、日記としての満足度・信頼性を保つ。

## 5. 明日ページ

### 5.1 ビューの再利用

明日ページの予定ビューは、**カレンダータブで日付を選んだときの日付詳細ビューと同じものを再利用** する。

- 実装が1つで済む
- カレンダーで明日をタップ＝今日タブで明日ページを開く、が同じ画面に着地して体験が一貫する

### 5.2 「明日の予定を組まなきゃ」と思わせる仕掛け

予定を立てる動機づけのため、以下を検討する。ただし **罪悪感を煽らない温度感** を厳守する。

| 仕掛け | 意図 | 温度感の注意 |
|---|---|---|
| カウントダウン | 「明日の予定編集まで残り○時間」など締切感で行動を促す | OK。締切の提示に留める |
| 未登録インジケータ | 明日に空き時間帯があるとき今日タブアイコンに小さなドット | OK。「空きがある」事実の提示に留める |

⚠️ **注意**：「24時間が埋まっていない＝悪」と強く出すと、埋めるためだけの予定（記録/予定の汚染）を誘発する。
インジケータは事実の提示に留め、「埋めろ」と命令しない。

### 5.3 未登録インジケータの導線

- 明日ページに未予定の空き gap があるとき、今日タブアイコンに小さなドットを出す。
- タップで明日ページの最初の空き gap にフォーカス。
- 既存の gap-tap 導線（08 §5・空きカードのタップで PlanCreateSheet を開く）をそのまま使う。

## 6. カレンダータブとの境界

| | 今日タブ | カレンダータブ |
|---|---|---|
| 範囲 | 昨日・今日・明日の3日のみ | それ以外の全期間（過去・未来） |
| 操作 | 上部タブ / 横スワイプで3ページ切替 | 月グリッドで任意の日へジャンプ |
| 性質 | 今を起点にした地続きの体験 | ランダムアクセス・俯瞰 |
| 日付詳細ビュー | 明日ページで再利用 | 日付タップで同じビューを開く |

- 明日ページとカレンダーの「明日」は同じビューに着地する（重複ではなく共有）。
- 明後日以降・昨日以前の特定日へはカレンダーから入る。今日タブは3日に閉じる。

- 確定事項（変えない）：
  - 3ページ固定（昨日・今日・明日）。起点は常に今日。
  - 日付ストリップ（日送りスクラブ）は不採用。
  - 昨日 = 振り返り（編集導線なし・主語は自分）、今日 = 記録、明日 = 予定。
  - 明日ページはカレンダー日付詳細ビューを再利用。
  - 今日タブは3日に閉じ、それ以外はカレンダータブ。
