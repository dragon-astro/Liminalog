# 09. プロフィール画面 情報設計

ユーザー設計セッション 2026-05-26 を経て、プロフィール画面の情報設計を確定する。
このドキュメントは [05-screen-flow.md](05-screen-flow.md) のプロフィール部分を上書きする。

---

## 0. 結論

プロフィール画面は **「分析」ではなく「自己表現」の場** として位置づける。

統計タブとの役割を以下のように分ける。

| タブ | 役割 | 動詞 | 視点 |
|---|---|---|---|
| 統計 | データで分析する | 分析する | 自分専用 |
| プロフィール | 自己表現・蓄積の見せ場 | 誇る・整える | 友達に見せる前提 |

**情報設計（何を出すか）は本ドキュメントで規範的に規定する。**
**UI（どう出すか）は他SNSの慣習を参照しつつ、実装側の最適化に委ねる。**

---

## 1. 設計原則

### 1.1 「友達に見せる前提」がフィルタ

各要素を採否判断するときは以下を問う。

- 友達に見せたとき意味があるか？
- 数字を見せる場合、それは「自慢になる」「個性が出る」数字か？
- 自分用の細かい分析データではないか？

NO に該当する要素はプロフィールに置かない（統計タブに回す）。

### 1.2 各要素は独立した意図を持つ

要素ごとに **「1行で言える意図」** を必ず書く。
意図が他要素と重複する場合は、どちらか一方に統合または廃止する。

### 1.3 設定・記録の雑多な集積にしない

設定系・管理系の項目は本体に出さない。すべて右上ハンバーガーメニュー（☰）に隔離する。
プロフィール本体は**ビジュアル要素と自己表現要素だけ**で構成する。

---

## 2. UIの参照モデル

具体的な配置・装飾・アニメーションは本書では規定しない。以下のSNSのプロフィールパターンを参照すること。

| 参照元 | 学ぶポイント |
|---|---|
| Instagram | 2ゾーン構造（ヘッダー + 投稿グリッド）、ハイライト円形横スクロール、☰隔離パターン |
| X (Twitter) | カバー画像 + 主要スタッツの並べ方、bioの扱い |
| BeReal | カレンダー型グリッド、過去蓄積を1画面で見せる手法 |

**実装者が新しいUIを発見した場合は本書に縛られず採用してよい。** 情報要素を満たし、設計原則に反しない限り自由。

---

## 3. 情報要素（MVP）

プロフィール本体に置く要素を以下に列挙する。順序・配置・サイズは実装裁量。

### 3.1 アイデンティティ要素（静的な自己紹介）

#### プロフィール画像
- **意図**: 自己同定
- ユーザーがフォトライブラリから選んで設定する画像（Instagram/X と同じ運用）
- 未設定時はニックネームの頭文字 + 背景色のフォールバック表示
- キャラクター・イラスト的なアバター（Memoji等）は前提としない

#### ニックネーム
- **意図**: 自己同定
- アプリ内で表示される名前。設定で変更可能

#### bio
- **意図**: 自己定義（自分の言葉で「どんな人か」を表現）
- 1〜2行程度の自由記述
- 任意（空でもプロフィールは成立する）
- 将来的には自動推測の提案機能を検討（Phase 2以降）

#### 主要スタッツ
- **意図**: 蓄積と継続の証
- 以下の数字を表示する。並べ方は実装裁量

| スタッツ | 意図 | 性質 |
|---|---|---|
| 🔥 ストリーク | 継続中の状態（loss aversion 装置） | 現在進行 |
| ⏱ 累計記録時間 | 長期的な投資の蓄積 | 蓄積 |
| 👥 友達数 | 横のつながりの広さ | Phase 3以降で意味を持つ |

**置かない数字:**
- スコア（変動する数字はプロフィールに不向き）
- 今週・今月の集計値（統計タブに置く）
- 予定通り率などの率系（同上）

### 3.2 達成要素（コレクション）

#### 解放コレクション
- **意図**: 達成の可視化（過去にやり遂げた証のショーケース）
- アンロックシステムで解放されたアイテムを表示
- 「飾る代表」を選べると自己表現の余地が出る（任意機能）
- 未解放アイテムを薄く見せて次の動機にするのもあり（自分ビューのみ）

### 3.3 蓄積コンテンツ要素（伸びていくもの）

#### 日記カードグリッド
- **意図**: 物語の蓄積（インスタの投稿グリッド相当）
- 毎日自動生成される DayDigest カードのアーカイブ
- 新しい順に表示
- タップで該当日のフルスクリーン表示
- 蓄積するほど画面が豊かになる = 長期使用への報酬

DayDigest の生成仕様は別途設計ドキュメントで扱う（Phase 2 設計タスク）。

## 4. プロフィールに置かないもの

以下は意図的にプロフィール本体から除外する。

| 要素 | 除外理由 | 行き先 |
|---|---|---|
| 詳細な統計チャート | 「分析」は統計タブの役割 | 統計タブ |
| カテゴリ別グラフ | 同上 | 統計タブ |
| 24時間ヒートマップ | 同上 | 統計タブ |
| 先週比・先月比 | 内向き分析 | 統計タブ |
| 365日マップ | 月間/年間ヒートマップと役割重複 + 日記グリッドの密度で代替 | 統計タブ（ヒートマップ）/ 日記グリッド |
| 設定項目 | 雑多な情報を本体に出さない | ☰ ハンバーガーメニュー |
| カテゴリ管理 | 同上 | ☰ ハンバーガーメニュー |
| データ管理 | 同上 | ☰ ハンバーガーメニュー |

## 5. 検討中・将来追加候補

以下は MVP では入れないが、Phase 2 以降に追加検討する。
追加する場合は「1行の意図」が独立していることを確認すること。

| 要素 | 候補意図 | 判断保留の理由 |
|---|---|---|
| 月アート | 月の印象を1枚に凝縮（日次より粗い粒度の自己表現） | 生成エンジンの実装コスト大、12ヶ月貯まるまで完成しない、ビジュアル生成は失敗が目立つ |
| ベストの日ピン留め | 自分が誇る日を上部固定 | UX 検証要、まず日記グリッドで様子を見る |
| テーマカラー | 主役カテゴリ色をプロフィールに反映 | 視覚ノイズになるリスク、検証要 |

## 6. ハンバーガーメニュー（☰）

プロフィール本体から隔離した設定・管理項目はすべてここに集約する。

### 構成方針

カテゴリ別にセクション分けする。具体的な階層・順序は実装裁量。

- **設定**: 1日の始まり時間 / 通知 / 公開設定 / テーマ・外観 / アカウント
- **管理**: カテゴリ管理 / カテゴリセット管理 / データのインポート・エクスポート
- **アプリ情報**: バージョン / ヘルプ・FAQ / プライバシーポリシー / 利用規約
- **アカウント操作**: ログアウト など

### 配置の基準

「**毎日触らない**」項目は全部ここに入れる。
プロフィール本体に出てよいのは「**見るだけで意味がある**」要素のみ。

---

## 7. 友達ビューとの差分

自分のプロフィールと友達のプロフィールは **同じレイアウト** を使う（Instagram/X と同じ慣習）。
コードは `viewMode: .own / .friend(User)` のような単一コンポーネントで分岐させる。

### 自分ビューと友達ビューの差分

| 要素 | 自分ビュー | 友達ビュー |
|---|---|---|
| ☰ ハンバーガー | ✅ 表示 | ❌ 非表示（代わりに ⋯ メニュー: ミュート・通報など） |
| プロフィール画像・名前・bio | 編集可 | 表示のみ |
| 主要スタッツ | ✅ | ✅ |
| 解放コレクション | ✅ 解放済み + 未解放を薄く（任意） | ✅ 解放済みのみ |
| 日記カードグリッド | ✅ 全件 | ✅ 公開設定でフィルタした分のみ |
| アクションボタン | なし | リアクション・フォロー・ミュート等 |

公開設定の粒度（日記カード単位 / 月単位 / カテゴリ単位）は Phase 3 で詳細設計する。

## 8. 実装上の自由度

### 8.1 規定する範囲

本書が**規定する**のは以下のみ。

- どんな情報要素を含めるか
- 各要素の意図（なぜそこにあるか）
- プロフィールに置かないものの境界
- ☰ への隔離方針
- 自分/友達ビューの差分

### 8.2 規定しない範囲

以下は実装側が自由に最適化してよい。

- 要素の配置・順序
- 要素のサイズ・色・装飾
- アニメーション・トランジション
- 視覚的なグルーピング方法
- 「ハイライト」「ハンバーガー」などのインスタ準拠用語が UI 文言として最適とは限らない
- 新規ビジュアル要素の追加（設計原則に反しない限り）
- ナビゲーション・サブ画面の構成

実装者が試行錯誤の中で本書より良い情報設計を発見した場合は、PR と共に本書の更新提案を行うこと。

---

## 9. テスト観点

- プロフィール本体に「毎日触らない設定項目」が露出していないこと
- ☰ から全ての設定項目に到達できること
- 友達ビューで自分専用の編集ボタンが表示されないこと
- 公開設定で非公開にした日記カードが友達ビューに出ないこと
- 日記が0件でもプロフィールが破綻しないこと（始めたばかりのユーザー対応）
- 解放アイテムが0件でもプロフィールが破綻しないこと

---

## 10. Claude/Codex への注意

- 本書は「**何を見せるか**」を規定する情報設計ドキュメント。「**どう見せるか**」は実装裁量
- インスタ・X・BeReal のプロフィール慣習を参照すること。発明する前に既存パターンを確認する
- 設定・管理系の項目を**プロフィール本体に追加してはいけない**。すべて ☰ に隔離
- 統計データを**プロフィール本体に追加してはいけない**。統計タブの役割
- 新しい要素を本体に追加するときは、まず「1行で言える意図」を書けるか確認する。書けない場合は追加しない
- 友達ビューと自分ビューは同レイアウトで実装する（別画面を作らない）
- 月アート・365日マップ・テーマカラー等の追加候補は本書 §5 に記録された判断保留の理由を踏まえること
