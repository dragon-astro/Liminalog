# 12. デイリーカード & コンテンツエンジン（楽しい総括 / 成長ループ）

「1日の総括を、見てて楽しく・シェアしたくなるものにする」ための情報設計。
2026-05-31 時点。[10-today-tab-structure.md](10-today-tab-structure.md)（今日タブ・昨日ページ）、[11-friends-design.md](11-friends-design.md)（友達・共有）、[04-data-model.md](04-data-model.md) を前提とし、10 §3.4 で保留していた **DayDigest（自動日記）の扱いを本ドキュメントで確定**する。

> 背景: ターゲットは中高〜大学生のショート動画ヘビーユーザー。「今日何してたっけ？」の可視化がコア価値で、友達と繋がる要素がフック。このカードは **製品の成長エンジン兼フック**であり、同時に「責めない気づき」を運ぶ器でもある。

## 0. 結論

- 毎日 **「今日のカード」** を1枚、データから自動生成する（文章生成AIは使わない＝決定論・コストゼロ・オフライン）。
- カードは **成長ループの心臓**：`良いカード → 外部SNS/LINEに貼る → 友達が見て気になる → 入ってくる → 同じ日を比較`。
- カードの「楽しさ」は **AIが生むのではなく、検出器 × 編集の声 × バリエーション** で生む。
- **単日はカード（表現・共有）、複数日は統計タブ（分析・私的）** で役割を分け、被りをなくす。
- 「楽しい見せ方」がそのまま **責めない自己直視（気づき）** になる。楽しさと気づきは同じものの表裏。

---

## 1. なぜカードが要るか（成長エンジン兼フック）

ソーシャルアプリは中身ではなく **拡散** で死ぬ。友達フックは友達0人だと無力（コールドスタート）。これを解くのがカード。

- **B（ソーシャル冷スタート）を解く**：友達は検索でなく "シェアされたカード" 経由で入る。
- **D（ビジュアル）を必須化**：貼りたくなる視覚品質がそのまま成長の燃料。Z世代は審美眼が高く、ここが弱いと拡散ゼロ。
- **A（初回体験）を解く**：友達0でも「自分の1日が良い感じにまとまる」が初回の報酬になる＝solo価値がシェア素材。

→ カードは「おまけのエクスポート機能」ではなく **製品の中核** として設計する。

## 2. 統計タブとの境界（単日＝カード / 複数日＝統計）

カード・昨日ページ・統計・カレンダー過去日が「1日の総括」を被って見せる問題を、**時間スコープ × 目的**で割って解消する。

| | デイリーカード（単日） | 統計タブ（複数日） |
|---|---|---|
| スコープ | 1日だけ | 週・月・年・**傾向** |
| 目的 | **表現・共有・感情** | **分析・私的・行動変容** |
| 操作 | 受け取る(push)／貼る | 掘りに行く(pull) |
| 形 | 1枚のパンチある視覚 | チャート・推移 |
| 共有 | する前提 | しない（自分用ツール） |

- **統計タブから "単日" モードを外す**（現 Dashboard の day ピッカーは退避）。単日を見たいときはその日の **カードを開く**。
- これにより統計タブは「単日の劣化ダッシュボード」をやめ、**「自分は時間をかけて変わってるか？」を映す唯一の鏡**という代替不可能な役割を得る（＝行動変容レバーのトレンド・対 過去の自分はここの仕事）。
- カードと統計は **同じ視覚言語（カテゴリ内訳の見せ方等）を共有**してよい。スコープが違えば重複でなく一貫性。

役割の補完関係：
- **カード＝「今日どうだった」**（瞬間・共有・感情）
- **統計＝「自分どう変わってる」**（パターン・私的・行動変容）

## 3. カードの2層構造

| 層 | 中身 | 目的 |
|---|---|---|
| 表（シェア面） | 1枚絵。称号 + パンチのある事実1〜3個 + スコア + ビジュアル（カテゴリ内訳等） | 貼りたくなる・一目で伝わる |
| 裏（展開） | カテゴリ別時間の数字、タイムライン、詳細インサイト | 単日を掘りたい欲求をカード内で満たす（統計タブに単日を置かない） |

- 表面が "貼れるパンチ" を担うので、生ログ全晒しの開示負荷を回避できる（→ §8 開示設計）。
- 展開層があるので「1日を数字で確認したい」も統計タブを経由せずカードで完結。

カードの置き場：**昨日ページがホーム**（受け取り＋シェア）。カレンダー過去日からも各日のカードを開ける。

## 4. コンテンツエンジンの原理（AIなし）

```
楽しさ = 良い検出器（データから"面白い事実"を見つける）
        × 強い編集の声（手書きの言い回しプール＝1回書けば資産）
        × バリエーション（パターン数 × ランダム）
```

- LLMの「その場で文章生成」は不要。**面白い事実を見つけ、人間が一度書いた"声"で喋らせる**だけ。
- すべて **決定論的に計算可能** ＝ ランニングコストゼロ・オフライン・破綻なし・声が一貫。
- 統計タブと共通の集計層（StatsEngine / PatternDetector）の上に乗せ、二重集計を避ける（[03/06] のエンジン方針に沿う）。

「楽しさ」が実際に宿るのは3箇所だけ：
1. **手書きの声**（同じ事実でも責めるか乗っかるかで別物。製品の人格）
2. **ペルソナ体系**（称号が "当たってる＆ちょっと笑える"）
3. **ビジュアル**（カードの絵そのものの満足感）

→ 難しいのは「生成」でなく **(a) 面白い人が声を一度書く (b) パターンを十分な数用意して飽きさせない**。個人開発で手が届く。

## 5. 検出器カタログ（拾える "面白い事実" の型）

すべて計算のみ。各型が複数の言い回しプールを持つ。**ただし下の2大原則がカタログ全体を縛る。**

### 5.0 二大原則（カタログの前提）

**原則1：アプリは活動の善悪を判定しない（中立がデフォルト）**
カスタムカテゴリがある以上、「散歩=良い／ショート=悪い」をアプリは知り得ない。だから：

- **褒める対象を、価値判断の要らないものに限定する**：
  - ✅ 予定との一致（行動の善悪でなく "自分の意図を守れた" を褒める）
  - ✅ 記録（事実としての更新。「自己最長」＝多いという事実）
  - ✅ 記録ストリーク（アプリ習慣であって活動の善悪じゃない）
- **カテゴリの増減を褒め/責めしない。事実だけ言う**：「ショート −30分」で止める（「えらい/ダメ」を付けない）。声の面白さは "観察と笑い・視覚化" で出す（「ショート4h ≈ 映画2本」は判定せず換算してるだけ）。
- **任意の抜け道**：カテゴリに本人が「**増やしたい / 減らしたい / どっちでもない**」を宣言できる。宣言があるカテゴリだけ「減らしたいって言ってたショート、−30分」と**正しく褒められる**（アプリが推測せず本人が決める）。行動変容ループ（§8.2）にも直結。**任意・後付け。デフォルトは中立。**
- これは弱さでなく正解。Z世代は説教くさいアプリを即嫌う。中立観察＋自分で宣言、が温度として合う。

**原則2：見出しは「大きさ」でなく「いつもと違う度（ルーティン逸脱）」で決める**
「今日の主役＝最長カテゴリ」だと毎日 睡眠になって退屈。だから：

- **ニュース価値 ＝ ルーティンからのズレ。** 睡眠・学校は毎日ほぼ同尺で出る＝高ルーティン → **見出しから降格**。
- ルーティン度は **カテゴリの意味を知らずに計算できる**（過去の出現頻度・時間帯・尺の分散＝規則性）。規則的なほど "定番" として減点、不規則・変化・初出・久々ほど "ニュース" として加点。
- 結果、カードは「今日 何が一番長かったか」でなく「**今日 何がいつもと違ったか**」を喋る。飽き（壁紙化）も同時に防ぐ。
  - 普段通りの睡眠8h → 黙殺。普段やらない料理 → 「初記録：料理 🍳」。いつもの月曜より勉強2h多い → ニュース化。

### 5.1 検出器カタログ（中立版）

依存：今日のみ / 履歴要 / タグ要 / 友達要 / 気分要。性格：🟢床（ほぼ毎日出る保険）/ 🔥パンチ（シェア向き）。例はドラフト（最終の声はユーザー編集）。

| 型 | 依存 | 性格 | 計算 | 例（中立・声はドラフト） |
|---|---|---|---|---|
| A. ルーティン逸脱 | 履歴 | 🔥 | 規則性からの乖離 | 「初記録：料理」「久々の運動（2週ぶり）」「今日の月曜、いつもと違う」 |
| B. 差分（対 昨日/曜日平均/自分平均） | 履歴 | 🔥 | 中立な増減 | 「ショート −30分」「いつもより夜更かし +1h」 |
| C. 記録・自己ベスト（事実） | 履歴 | 🔥 | max/min | 「勉強の自己最長 3h 👑」「今週いちばんの集中」 |
| D. 1日の形・構造 | 今日 | 🔥 | 集中の塊/細切れ/重心 | 「3時間ぶっ通し（スプリンター）」「重心は夜22時」（§6の素） |
| E. 時間帯パターン | 履歴 | 🔥 | 時間帯クラスタ | 「集中できるのは朝9–11時」「23時以降に○○が増える」 |
| F. 予定との一致 | 今日 | 🟢🔥 | plan vs actual | 「有言実行率 80%」「立てた予定、完遂」（**安全に褒められる**） |
| G. カテゴリ/タグ構成（事実のみ） | (タグ) | 🟢 | 割合 | 「今日の9割が娯楽、潔い」「学習・休息・娯楽で三分割」（善悪は付けない） |
| H. 体感換算 | 換算表 | 🔥 | 静的換算 | 「ショート4h ≈ 映画2本」「通学 往復2h ≈ 年20日」 |
| I. 記録ストリーク・累計（アプリ習慣） | 履歴 | 🟢 | streak/累計 | 「5日連続で記録」「記録100日 🎉」（**安全に褒められる**） |
| J. 気分（任意） | 気分 | 🟢 | mood集計 | 「今日は😊多め」「疲れマーク多い日」 |
| K. 対 友達（当事者性を主に） | 友達 | 🔥 | 一致/共起 | 「今日3人が勉強してた」「Mikaと同時刻に就寝（偶然）」※競争は従（11/温度） |
| L. ユーザー宣言ベースの応援（任意・原則1） | 宣言+履歴 | 🔥 | 宣言×差分 | 「減らしたい ショート、−30分」「増やしたい 運動、+40分」 |

**降格/中立化したもの（旧カタログから変更）**：
- 旧「最長＝今日の主役」→ 生の最長（睡眠）は見出しにしない。A（逸脱）/ D（形）に作り替え。
- 旧 G「カテゴリ褒め」→ 事実のみ（「えらい/ダメ」削除）。
- 旧「減ってえらい」→ 原則1で削除。ただし L（ユーザー宣言）でのみ復活。
- 「睡眠不足」等の責め → 中立事実に留め、頻度を絞る。

### 5.2 選抜ロジック

検出器は毎日複数発火するので、1枚への選抜が要る：

1. 各検出器が `(事実, パンチ度, 型, ルーティン逸脱度)` を返す。
2. **パンチ度 × ルーティン逸脱度** で上位を採り、**型の重複回避**（昨日と同じ型を避ける＝飽き防止）。称号1 + 事実1〜3 に絞る。
3. **🟢床（F/I/G）は何も無い日の保険**。🔥が無ければ床で埋め、カードを寂しくさせない。
4. ネガ寄り（H睡眠不足・K競争）は**頻度を絞る**（毎日責めると壁紙化＆離脱）。
5. 換算表（H）は **カテゴリ別 "あるある換算"** を手書きで用意（資産）。

### 5.3 ルーティン逸脱度の計算（原則2のエンジン）

カテゴリの意味を一切使わず、**過去の自分のデータだけ**から「いつもと違う度」を点数化する。重い統計は不要（mean/std/頻度のみ）。

**ステップ1：カテゴリごとの平常（ローリング基準・直近28日）**
各カテゴリ c について履歴から：
- `reg_c` 規則性：出現頻度（N日中 何日出たか、0〜1）
- `μ_c, σ_c`：1日あたり分数の平均・標準偏差（`σ` には下限 **15分** floor）
- `typical_start_c`：開始時刻の代表値
- 最終出現日（"久々" 判定用）

**ステップ2：今日のニュース価値（per カテゴリ）**
```
newsworthiness_c =
    w1 · |z| · (1 − reg_c)     // 量のズレ。"定番"ほど (1−reg) で割引
  + w2 · novelty               // 過去0回の初出現
  + w3 · f(空白日数)            // ≥10日ぶり出現＝久々
  + w4 · timing_dev            // typical_start から ±2h 以上ズレ
   z = (今日の分数 − μ_c) / σ_c
```
- `(1 − reg_c)` がキモ：**高ルーティン（睡眠等）は量が大きくても自動降格**。
- `|z| ≥ 1.5` 未満は黙る。重み `w1..w4` は実装で調整（最初は同程度）。

**つまずき対策**
- **コールドスタート**：履歴 **< 7日** は逸脱検出オフ。床型（F/I/G/D）で回す。
- **σ極小**：floor 15分で z 暴発を防ぐ。
- **曜日対応（任意・後回し可）**：学校等は基準を曜日別に持つと「いつもの月曜より」が正確。28日窓で各曜日約4サンプル。

**どこに効くか（一石二鳥）**
- §5.2 選抜：`パンチ度 × newsworthiness` で1枚に載せる事実を選ぶ。
- §6 ペルソナ副軸：「崩壊/カオス」は timing_dev / z をそのまま使う。

### 5.4 「睡眠（主要休息ブロック）」はカテゴリ名でなくパターンで特定

§5 原則の延長で、**睡眠もカテゴリ名・デフォルト有無に依存しない**。デフォルトカテゴリ（睡眠/休息等）は **ただの初期例。削除・改名・自由**。非削除の中核にはしない。

**判定基準（時計の"夜"に依存しない）**
睡眠を特徴づけるのは時計位置でなく形：
1. 長い連続ブロック（無切替・例 ≥3〜4h）＝尺
2. ほぼ毎日・同じ位相で繰り返す＝規則性
3. その人史上いちばん安定して長い休息クラスタ ＝ 主要休息ブロック（睡眠）

→ 履歴の長い無切替ブロックを **開始位相で円環クラスタリング**し、最も "毎日・同位相・長い" 塊を採用。**朝3時でも昼1時でも関係ない**（昼夜逆転は塊が昼に座るだけ）。

**2つの参照を使い分ける（昼夜逆転対応）**
- **クロノタイプ（朝型/夜型）＝絶対時計**。夜に活動 → 深夜型（＝正しいラベル）。
- **崩壊（リズム乱れ）＝自分の平常**。安定した昼夜逆転は崩壊でない（一貫している）。社会の"普通の夜"とは比べない。

**自信度で出し分け（ガチ崩壊・無記録対応）**
規則クラスタが立たない人は "どれが睡眠か" を高信頼に言えない。嘘をつかず、検出ごとに必要な確度で出し分ける：

| 検出 | 必要な睡眠確度 | 低確度時 |
|---|---|---|
| クロノタイプ（重心の休息除外） | 低（だいたい除けば可） | その日の最長休息で代用 |
| 睡眠不足・充電デー | 高（"これは睡眠"と断言要） | **黙る**（or 任意タグで発火） |
| 崩壊判定 | 自分の平常が要る | 平常が無ければ発火しない |

- **崩壊型に毎日「崩壊！」と言わない**：崩壊が平常な人には比べる平常が無く、発火しない（＝責めない・正しい）。逆に**たまの規則的な日が "今日めずらしく整ってる" ニュース**になる。慢性的不規則は日々の鞭でなく**持続ペルソナ（カオス型）**として扱う。
- 睡眠が全く拾えない日 → 睡眠依存検出を全スキップし、睡眠不要の検出でカードを作る。
- 本人が睡眠ネタを使いたい → **任意の「これは睡眠」タグ**が手動オーバーライド（強制しない）。
- 実装注意：0:00区切りで「23時〜7時」睡眠が2日に割れるため、クラスタリングは**日跨ぎ前の生チャプター時刻**で見る。

**「休息」の扱い（充電デー含む・カテゴリ名に依存しない）**
- アプリが特別扱いする休息は **主要休息ブロック（睡眠）1個だけ**。「休息」カテゴリ名では拾わない（デフォルトの休息カテゴリは初期例・削除可）。
- **充電デー** ＝ 主要休息ブロックが自分平均より大幅に長い（例 >10〜12h）or 非睡眠の記録活動が極小。**「休息カテゴリ」は不要・純粋計算**。
- **昼寝・起きたままの休憩・横になってショート等は休息として特別扱いしない**（意味を知らないため）。通常の短い活動ブロックとして数える。→ 例「14時間ショート漬け」は充電デーでなく「ショートの沼の主」、「14時間寝た」は充電デー。

**貫く原則**：**計算できることだけ言う。自信が無いものは黙る。失敗モード（リズム無し）自体が有効なシグナル（カオス称号）になる。** 無理に睡眠を断定するより、少なく・正確に喋る方がターゲットに信用される。

## 6. ペルソナ / 称号体系（シェアの心臓）

**性格診断の結果のように、実データから称号が出る。** Z世代がスクショして貼る一番の動機。

### 6.1 称号名は「1日の形」から作る（中立・カテゴリ非依存）

§5 原則（中立・カスタムカテゴリOK）の縛りの中で作る。鍵は——**称号名は、カテゴリの意味を知らなくても出せる「1日の形」から作る**。形（いつ・どんな集中で動いたか）はカテゴリ非依存かつ中立に計算できる。具体名（ショート等）は称号名でなく**説明文に事実として**差し込む。

**主軸（称号名を決める）2本 → 4×3＝12種：**

- **① 時間帯の重心（クロノタイプ）**：朝 / 昼 / 夜 / 深夜
- **② 集中の形**：スプリンター（長時間少数）/ マラソナー（コンスタント）/ ザッピング（細切れ多数切替）

| | スプリンター | マラソナー | ザッピング |
|---|---|---|---|
| **朝** | 朝の短距離走者 | 早起きコツコツ | 朝からせわしない |
| **昼** | 昼の集中砲 | 平常運転マスター | マルチタスク昼 |
| **夜** | 夜型スプリンター | 宵っ張りの持久型 | 夜のザッピング |
| **深夜** | 丑三つの天才 | 不眠の修行僧 | 体内時計バグり気味 |

（名前は全てドラフト。最終はユーザー編集。誰でも・毎日・中立に出る。「朝型/夜型」は自認が強くシェアされやすい）

**副軸（称号名でなく説明文を彩る／サブ称号）：** 規則 vs 崩壊 / 計画 vs 即興 / 記録の濃さ。

→ 称号 ＝ **名前（12）＋ 具体事実を織り込んだ説明文**。例：
> **夜のザッピング** ｜ 22時以降に5回切替、今日の主戦場はショート。計画は3割、出たとこ勝負の夜。

名前は星座のように "安定して自認できる"、説明文が毎日 "自分だけ" を作る。

### 6.2 レア称号（出にくい＝出ると貼りたくなる）

エッジケース専用。中立を保つ。
- リズム崩壊 → 「時差ボケの人」「体内時計こわれた」（§6.4 の理由で "宇宙飛行士" は不採用寄り）
- 記録空白だらけ → 「ミステリアスな1日」
- 完全計画通り → 「有言実行の人」
- ノープラン即興 → 「風まかせ」
- 初記録カテゴリ → 「今日デビュー：◯◯ 🍳」
- 睡眠ばかり → 「充電デー 🔋」（責めず "充電" と中立に言い換え）

レアは確率的に "おっ" となり、シェア動機が最強。

### 6.3 数とバリエーション

- **目標：称号名 20〜30個**（形12 ＋ レア8〜15）。**MVP は 15〜20**（形12 ＋ レア5〜8）。
- **称号数 ≠ 体感バリエーション**。体感 ＝ `称号名(25) × 説明文(副軸) × 織り込む事実(検出器) × その日の数字` ＝ 実質数百種。**名前を無理に増やさない。**
- **量より質**：25個を作り込む >> 100個の量産（薄い称号はテンプレ感で逆効果）。コスト＝1称号 名前＋言い回し5〜8個 ≒ 全体150〜200行の手書き資産（一度きり）。
- コレクション観点でも 25前後が最適（集めきれる数＝「12星座集める」感覚。500個は無意味化）。
- 称号は**データ駆動**にしてコード変更なしで後から追加可（運用で増やす）。

### 6.4 ネーミング原則：面白い ∧ 何を言ってるか分かる

面白い言い回しは最重要だが、**メタファーが意味と繋がってないと「何が言いたいのか分からない」**になる（例：「宇宙飛行士」⇄「生活リズム崩壊」は連想が遠く、伝わらない）。

- 名前はオチャメ・オブリークでよいが、**指してる事実への "連想の橋" が見つかること**。読み手が「あ、◯◯だからか」とすぐ腑に落ちる比喩を選ぶ。
- **説明文が伝わりやすさを担保する**。名前が多少ひねっていても、説明文が中立な事実を述べるので意味は絶対に迷子にならない。名前で攻め、説明文で受ける。
- 連想が遠すぎる比喩は避ける（宇宙飛行士の轍）。「時差ボケ」「体内時計バグった」のように、**笑える＆リンクが感じられる**方を取る。

### 6.5 2階建て＋コレクション（装飾経済との接続）

- **日替わり称号**＝カードに乗る（毎日変わる＝新鮮・シェア素材）。
- **持続タイプ**＝数週間の支配的称号をプロフィールに（「あなたは基本 夜型スプリンター」）＝アイデンティティ。
- **「今まで出した称号」をコレクション化** → 09 の装飾経済の "薄い/ガワだけ" 問題をここで埋める。汎用バッジ（ルーキー）より、**自分が実際に送った1日の記録＝称号コレクション**の方が personal で集めたくなる。

### 6.6 判定閾値（デフォルト・全てチューニング前提）

実機で「スプリンター出すぎ」等を見て直す前提のマジックナンバー。「睡眠」は §5.4 の **主要休息ブロック（パターン検出）** を指す。

**主軸①クロノタイプ**（主要休息ブロックを除いた活動の「中央時刻」・絶対時計）
| 型 | 条件 |
|---|---|
| 深夜型 | 0:00–5:00 に活動 ≥60分（最優先・上書き） |
| 朝型 | 中央時刻 < 11:00 |
| 昼型 | 11:00–16:00 |
| 夜型 | ≥ 16:00 |

**主軸②集中の形**（上から先に当たった方）
| 型 | 条件 |
|---|---|
| スプリンター | 最長ブロック ≥ 90分 |
| ザッピング | 非休息チャプター ≥ 8個 かつ 中央尺 < 25分 |
| マラソナー | 上記以外 |

**副軸**
| 軸 | 値 | 閾値 |
|---|---|---|
| 規則/崩壊 | 崩壊 | 起床 or 就寝が自分平均から ±2時間以上（§5.4 自己相対） |
| 計画/即興 | 計画派 / 即興 | 予定一致率 ≥70% / <40% or 予定なし |
| 記録の濃さ | 几帳面 / ざっくり | 記録カバー ≥18h / <10h |

> 温度＝**自虐×あたたかい**で確定（ユーザー選択）。以下 §6.7 に Claude が実コピーを具体指定する（Codex は実装するだけ）。

### 6.7 称号コピー・カタログ（Claude 指定・実装用）

**声の定義**：自虐×あたたかい。**茶化す対象は "時間と形"（夜ふかし・ザッピング・カオス）だけ。活動の善悪は絶対に裁かない**（§5原則1）。Gen-Z のカジュアル、一緒に笑う。

**スロット**：`{focus}`=ドミナント裁量カテゴリ名 / `{dur}`=その時間 / `{n}`=切替回数 / `{cat}`=対象カテゴリ / `{gap}`=○日ぶり。
**実装ルール**：各称号は message を**配列で持ちランダム選択**（飽き防止）。signalMessage（逸脱・§5.3）が発火した日はそれを優先し、**タイトルも逸脱に整合**（B是正）。床/コールドスタート時も**メタ文言（「データが少ない」等）を出さず**自虐コピーで埋める（C是正）。

#### 形ベース（タイトル＝`{chrono}` ＋ 下記。`{chrono}`＝朝の/昼の/夜の/深夜の）

## 7. 編集の声（トーンガイド・要作り込み）

- 基本トーン：**責めない・自虐に乗っかる・軽くハイプ**。「ショート4時間、潔い才能」のように、ダメ出しでなく一緒に笑う。
- 同じ事実に複数の言い回し（各5〜10）。ランダムで飽きを防ぐ。
- 毎日同じ数字（「4h」）を出さない。**角度を変えた発見**を回す（曜日傾向・時間帯・換算など）＝壁紙化（慣れて諦めに固まる）を防ぐ。
- 詳細トーンガイドは別途（声の主が確定する）。

## 8. 行動変容・開示設計との接続

### 8.1 楽しさ＝責めない鏡

「ショート4時間 ≈ 映画2本」は笑えるが刺さる。称号「ショートの錬金術師」は自覚を笑いに変える。
**楽しい見せ方こそが、責めない気づき。** 気づき（事実）と楽しさ（声）は対立しない。

### 8.2 気づき → 予定への橋（最重要・[10] と連動）

カードは「見せて終わり」にしない。**気づいた直後＝唯一行動を変えられる瞬間**に、明日の予定立てへ流す。

- 昨日カードに「**明日はどうする？**」を1つ。ショートが起きがちな時間帯に小さな代替ブロックを1個プリフィルして提案。
- 曖昧な後悔を「明日22時に散歩30分」という具体的 if-then に1タップで変換する。

### 8.3 開示（公開）設計

- **公開するのは抽象側（称号・スコア・盛れる総括カード表面）**。
- **詳細タイムライン（ショート4hが映る所）は私的**。生ログ全晒しの重さを回避（[11] 公開設定に従う）。
- カードのシェアは "貼れる表面" のみ。展開層（裏）は本人だけ。

## 9. シェア & 流入導線（成長ループ）

1. 毎日カードが生成される（昨日ページで受け取る）。
2. カード表面をワンタップで **画像書き出し → 外部（ストーリー/LINE等）へ**（[11] のプロフィール共有とは別に、カード固有のシェア）。
3. 貼られたカードを見た友達が **ワンタップで参加 → 自分の同じ日と比較**（[11] 比較体験へ接続）。
4. 比較が友達フックを発火させ、継続記録の動機になる。

→ カードの視覚品質と "貼りたくなる度" が、そのまま CAC ゼロの成長エンジン。

## 10. 技術メモ

- **決定論・ゼロランニングコスト・オフライン**が原則。サーバーLLMは使わない。
- どうしても文章の揺らぎが欲しい場合の逃げ道：**Apple Intelligence の on-device Foundation Models（iOS 26、端末内推論＝サーバー代ゼロ）** をテンプレの上の "味付け" として任意利用。ただし **主役はテンプレ**で、AIなしで完全に成立する設計にする（対応端末・品質・遅延の不確実性に依存しない）。
- 集計は統計タブと共通の StatsEngine / PatternDetector を再利用（二重集計回避）。
- カードのデータは単日スナップショットとして保持しうる（履歴で過去日のカードを再描画）。詳細は [04] で別途。
