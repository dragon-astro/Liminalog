## 読む順序

```
01 (現状把握) → 02 (ギャップ抽出) → 03 (方針確定) → 04 (DB詳細) → 05 (画面詳細) → 06 (テスト) → 07 (計画レビュー) → 08 (タイムライン再設計) → 09 (プロフィール情報設計) → 10 (今日タブ3ページ構成) → 11 (友達機能設計) → 12 (デイリーカード/コンテンツエンジン) → 13 (ビジュアル・アイデンティティ)
```

- **01〜02** は「現状を言語化」するフェーズ。実装を変えず、コードと仕様を読み解く
- **03〜06** は「これからの方針」を決めるフェーズ。01〜02 を踏まえて意思決定する
- **07** は Codex のレビュー結果。Claude が次に docs を更新する前に必ず確認する
- **08** はタイムライン UI 再設計。24時間バー + 固定高さカードリスト方針として、05 のタイムライン部分を上書き
- **09** はプロフィール画面の情報設計 v2。自分ビュー/他人ビューの二面性 + 装飾アイテム経済を確定。05 のプロフィール部分を上書き
- **10** は今日タブの 3ページ構成（昨日=振り返り / 今日=記録 / 明日=予定）。日付ストリップ不採用・3日に閉じる方針を確定。05 の今日まわりを上書きし、08 の親構造になる
- **11** は友達機能・友達タブの情報設計。一覧（ランキング帯+ステータス）と友達詳細（09 他人ビュー再利用）の2層、比較はデイビュー再利用、競争の温度設計を確定。05 の友達画面を上書き
- **12** はデイリーカードとコンテンツエンジン。1日の総括カードを成長ループの中核に据え、楽しさは「検出器×声×バリエーション」（AIなし）で作る。単日=カード/複数日=統計の境界を確定し、10 §3.4 の DayDigest 保留を統合
- **13** はビジュアル・アイデンティティ。liminal（予定と実績のあいだ）の世界観を、トワイライト/ダークファーストのカラー・タイポ・空気感、signature の二重24時間リング、カード視覚仕様まで具体値で落とし、Codex が世界観を再現できるようにする

## このドキュメント群とのつき合い方

- **仕様書 (`Liminalog/liminalog_spec_v04.md`)**: プロダクトの What / Why。変更時はバージョンを上げる
- **AI_TASKS.md**: 実装タスクの進捗管理。設計が確定したらここに反映する
- **本ドキュメント (`docs/`)**: 実装の How。設計変更が発生したら該当ファイルを更新

設計変更時のフロー:
1. 該当の `docs/*.md` を更新
2. `AI_TASKS.md` のタスクを追加・修正
3. 影響範囲が大きい場合は `liminalog_spec_v04.md` も更新
