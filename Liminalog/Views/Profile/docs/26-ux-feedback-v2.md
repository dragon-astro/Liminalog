# 26. UXフィードバック v2 — 密度・視認性・直接操作・性能

`24-ux-improvements-batch.md` の実装後に得たユーザーフィードバックを正準化する。v1の機能数を増やすことではなく、**画面を占有しない・既存操作より分かりやすい・誤操作や震えがない**状態へ仕上げ直す。

## 1. 運用

- 統合ブランチ: `codex/ux-feedback-v2`
- 実行順: A → B → C → D → E → F → G
- Itemごとに専用ブランチ・実装コミット・検証・no-ffマージを行う。
- 未検証、失敗中、設計未確定のItemは統合しない。
- `codex/ux-improvements-v1`、`codex/monetization-foundation`、`main` へはユーザー承認なしにマージしない。

## 2. 共通原則

- UI追加そのものを成果にしない。常駐操作を増やす場合は認知負荷を検証する。
- 見た目をコンパクトにしつつ、アクセシビリティ上の操作領域とラベルは確保する。
- LiminalThemeのセマンティックトークンを使い、hexを直書きしない。
- CloudKit、SwiftData、共有、既読化、課金の既存ポリシーを不用意に変更しない。
- 性能とドラッグ品質はDebug Simulatorの体感だけで判断しない。
- 実行中カードの予定/実績同居、タイムライン内カテゴリ作成→即選択、4段階ズームは維持する。

## 3. Item A — 実行中カードのコンパクト化

- 停止と公開設定のための独立した大きな行を廃止し、カテゴリ名・経過時間と同じ情報行の末尾へ戻す。
- 視覚はアイコン中心にし、透明な操作領域とaccessibility label/valueで操作性を保つ。
- 予定あり/なしの双方でv1 Item F以前と同程度の高さにする。
- 予定/実績同居、ChapterStore API、エラー処理は変更しない。

## 4. Item B — カテゴリ選択のコントラスト修正

- 選択中の黒文字固定と濃い不透明背景を廃止し、軽い半透明表現へ戻す。
- 淡色/濃色カテゴリ、曙/宵で読めるセマンティックな文字色を使う。
- ホーム「明日」、Calendar日間/週間を共通表示に保つ。
- その場カテゴリ作成と即選択は維持する。

## 5. Item C — 従来グリッド＋全アイコンライブラリ

- CategoryEditSheetでは旧候補を中心としたコンパクトグリッドを最初に表示する。
- グリッドの「＋」からのみ、200件・ジャンル・検索・必要ならピン留めを備えたライブラリsheetを開く。
- 選択後はsheetを閉じて元画面へ即反映する。
- 旧候補、未収載の保存済みicon文字列、実在SF Symbols検査、永続化を維持する。

## 6. Item D — 過去日の予定追加ガード

- 過去日で時間指定不可を終日予定へ変換して制限を迂回しない。
- 昨日以前の日セルから予定作成sheetを開かない。
- 今日/未来日は既存PlanStoreポリシーに合わせる。
- 日付境界、タイムゾーン、月跨ぎをテスト可能なポリシーへ切り出す。

## 7. Item E — 価値のある友達長押しメニュー

- シングルタップは詳細を開く既存挙動を維持する。
- 長押しから、既存APIによる詳細、友達解除、ブロックへ入れる。
- 破壊的操作はroleと確認ダイアログを持ち、キャンセルでは変更しない。
- CloudKit、共有、FriendSet、blocked状態の既存更新経路を再利用する。

## 8. Item F — カテゴリボード切替の軽量化

- SwiftData、Widget、Live Activity、共有、選択同期、View再生成をReleaseで切り分ける。
- スワイプ中の中間ページでは重い副作用を行わず、確定後に同一IDあたり一度だけ反映する。
- スワイプ、タイトルメニュー、ページドット、再起動後保持を維持する。
- iPhone 13を含むRelease実機で改善前後を記録する。

## 9. Item G — タイムライン直接操作の再設計

### 9.1 設計ゲート

次の3案を、発見性・常駐密度・誤操作・片手操作・VoiceOver・移動/resize競合で比較する。

1. メイン/サブの2ハンドル
2. 1ハンドル＋ドラッグ中だけ表示する15/5/1分切替
3. 1ハンドル＋長押し等の一時精密モード

第一候補は **1ハンドル＋必要時だけ現れる精度切替**。明確に優れた案がなければ恒久UI実装前にユーザーへ確認する。

### 9.2 ヒット判定

- resizeハンドルの横方向ヒット領域をブロック本体へ侵入させない。
- 移動、開始resize、終了resizeのgesture arbitrationを明確にする。
- 視覚を大きくせず、必要な操作領域は縦方向/専用領域で確保する。

### 9.3 スナップと震え

- 15分を標準、5分と1分を精密調整として選べる。
- ドラッグ開始時刻と開始座標を固定基準にし、translationから未丸め時刻を算出して最後に量子化する。
- 既に丸めた前フレーム値へ差分を再加算しない。
- autoscrollと座標変換を分離し、必要なら境界にhysteresisを設ける。
- 同方向の入力中に時刻が逆行せず、数ポイントで遠距離へ飛ばないことを純粋ロジックテストで固定する。
- 移動、開始resize、終了resize、4ズーム、autoscroll、日付境界をRelease実機動画で確認する。

## 10. 最終合格条件

- A〜Gの全受け入れ基準、LiminalogTests全件、主要回帰、課金9 suite、generic iOS Release、課金readinessが成功する。
- 曙/宵、再起動永続化、過去日拒否、15/5/1分の移動/resize、Release実機性能を証拠付きで確認する。
- `codex/ux-improvements-v1..codex/ux-feedback-v2` の課金禁止パス差分がゼロで、AI_TASKSとGit履歴が一致し、作業ツリーがcleanである。
