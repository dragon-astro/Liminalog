# Liminalog — アプリ仕様書 v0.4

## 概要

**アプリ名:** Liminalog  
**コンセプト:** タイムトラッカーの記録の煩わしさを、友達との達成スコア競争というゲーム性で解消し、予定を立てる・予定通りに動く・振り返るという習慣を楽しく身につけられるアプリ。  
**ターゲット:** 自己管理したい気持ちはあるけど続かない18〜22歳の大学生・専門学生  
**一言で言うと:** 24時間の予定を立てて、記録して、友達とスコアで競う。

---

## 思想・背景

若者が辛いと感じることをゲーム・SNS・友達という要素でカモフラージュして、気づいたら習慣になってる体験を作る。勉強・自己管理・振り返りといった意識高い行動を、楽しくやれるようにしたい。（クオリアと共通する思想）

---

## アーキテクチャ方針

- **ローカルファースト:** SwiftData でオンデバイス保存
- **クラウド同期:** CloudKit + CKShare + CKSubscription（友達共有・マルチデバイス）
- **バックエンドレス:** 外部サーバー不要・UGC依存なし
- **ウィジェット推奨:** 日常の記録導線は WidgetKit がメイン

---

## 友達機能の実装方針

- ユーザー全員のフィードではなく承認した友達のデータのみ取得（BeReal方式）
- 承認制の相互フォロー関係
- CKShare でチャプターレコードを友達と共有
- CKSubscription でレコード更新時にバックグラウンド取得
- 完全サーバーレス・無料で実現可能

```
User A のチャプターレコード
→ 公開設定に基づいて CKShare で友達 B と共有
→ CKSubscription で更新を検知
→ 友達 B のデバイスでレコードを Fetch
→ ウィジェットに反映
```

### 2. カレンダータブ

**役割:** 日付単位の俯瞰と、重要な予定から詳細な24時間予定へ落とし込む計画導線。

#### 月カレンダー画面（全画面）
- 月単位のカレンダーグリッド
- 各日に **スコアバッジ** を表示
- 月表示には **重要な予定だけ** を表示する
- 24時間分の詳細予定や実績チャプターは月表示に出さない
- 複数日にまたがる重要な予定は、日をまたいで繋がる横長ラベルとして表示する
- 日付タップ → デイビュー（全画面）に遷移

#### デイビュー（全画面）
```
┌─────────────────────────┐
│ ← 5月21日 水曜日         │  ← 戻るボタン
├─────────────────────────┤
│ 重要な予定エリア          │
│ 📅 ゼミ発表              │
│ ✅ 課題提出              │
├─────────────────────────┤
│ タイムライン              │
│ 09:00 ━━━━━ 勉強        │
│ 11:30 ━━━ 休憩          │
│ 13:00 ━━━━━━ 趣味      │
│ ── 14:00 授業 ──        │  ← カレンダー予定（うっすら）
│ 16:00 ━━━━ 勉強        │
└─────────────────────────┘
左右スワイプで前後の日に移動
```

**重要な予定エリア**
- 「時間は未定だが、この日にやる大事なこと」を置く
- 現行実装では `PlanBlock.isImportant == true` を重要な予定として扱う
- `isAllDay == true` は「時間未指定」を表す。既存データ互換のため `isAllDay == true` も重要予定として表示する
- 時間つき予定でも `isImportant == true` なら月カレンダーに表示し、開始時刻も表示する
- 重要な予定は追加・編集・削除可能
- 近い日付になったら、重要な予定をもとに日別タイムラインで時間つき予定へ落とし込む
- 複数日にまたがる重要な予定はDBでは分割しない

**タイムラインエリア**
- チャプターの記録（カラーバー＋カテゴリ名＋時間）
- 時間つき予定 (`PlanBlock.isAllDay == false`) と実績をカード形式で表示
- 未来の日付では現在記録中の Chapter を継続中として表示しない
- 友達のカレンダー予定も公開設定に基づいて表示
- 予定/実績タップ → 詳細表示＋編集
- カレンダー画面では空白時間帯から新規チャプター記録はしない（予定作成のみ）
- 長押し → 削除・移動メニュー
- 公開設定ボタン（該当日の設定をその場で変更可能）

**外部カレンダー連携（将来）**
- 時間未指定/終日予定 → 時間未指定の重要予定として取り込む
- 時間指定予定 → タイムラインの時間つき予定として取り込む。必要なら `isImportant` を付けて月カレンダーにも表示
- 友達機能の方が優先度は高いため、外部連携は後回し

**日付またぎの処理**
- DBは分割なし・1レコードで保存（startTime・endTimeをそのまま記録）
- スコア計算時のみメモリ上で0:00仮想分割して処理
- タイムライン表示は 0:00-24:00 固定でクリップする
- ユーザーには分割を見せない

## スコア計算仕様

```
スコア = カテゴリ合計時間達成率 × 80% + 時間軸一致率 × 20%
```

**カテゴリ合計時間達成率（80%）**
- カテゴリごとに予定時間に対する実績時間の達成率を計算
- 超過分は切り捨て（100溢れ防止）
- やむを得ない時間変更に強い設計

**時間軸一致率（20%）**
- 1440分を1分ずつの点として計算
- 予定と実績が重なった時間が得点になる
- 境界は±15分の許容誤差

**計算例**
```
予定: 勉強 9:00〜11:00（120分）
実績: 勉強 10:00〜12:00（120分）

合計時間: 120/120 = 100% × 0.8 = 80点
時間軸: 予定と重なった時間 10:00〜11:00 = 60分
        ±15分許容後も60分のまま
        60/120 = 50% × 0.2 = 10点
合計スコア: 90点

---

予定: 勉強 9:00〜11:00（120分）
実績: 勉強 9:10〜11:10（120分）

合計時間: 120/120 = 100% × 0.8 = 80点
時間軸: 厳密な重なり 9:10〜11:00 = 110分
        ±15分許容後: 9:00〜11:10 = 120分全部OK
        120/120 = 100% × 0.2 = 20点
合計スコア: 100点
```

**前提条件**
- 24時間を空白なく予定で埋める（自由時間も含む）
- 正直な記録かどうかは友達というフィルターが担保する
- 自由時間を多く設定した予定は友達にバレる設計

**スコア公平性のための編集ロック**
- 当日のスコアは「前日までに組んだ予定」と「当日の実績」を比較する
- 予定は **明日以降** のみ新規追加・内容/カテゴリ/時間変更・削除できる
- 今日以前の時間つき予定は、内容・カテゴリ・時間を固定する。重要フラグ・メモ・公開設定は後から編集できる
- 例外として、時間未指定の重要予定 (`isAllDay == true`) はスコア計算から除外されるため、過去日・今日・複数日またぎでも後から追加・編集・削除できる
- ただし時間未指定の重要予定を時間つき予定へ変換する場合は、スコア対象になるため明日以降の日付でなければ保存できない
- 実績は **当日中** のみカテゴリ・開始時刻・終了時刻・削除を許可する
- 前日以前の実績は、カテゴリ・開始時刻・終了時刻・削除をロックする。後から編集できるのはメモ・場所・公開設定のみ
- 将来、前日以前の実績時間修正をどうしても許可する場合は、変更履歴が後から見える監査表示を必須にする

## ストリーク仕様

- **条件:** その日のスコアが60%以上の日が連続していること
- **閾値60%の意図:** 赤点ラインのイメージで身近な数字。普段の予定の範囲内で割と簡単に達成できる
- **インセンティブ:** 雑な予定を立てると当日逸脱しやすくなり60%を下回るリスクが上がる。丁寧な予定を立てると達成しやすくストリーク維持しやすい
- **目的:** 毎日予定を立てるモチベーションと精度の高い予定を立てるインセンティブを同時に働かせる

## 1分ルール

- チャプター切り替え後1分以内に別のチャプターに切り替えた場合、前のチャプターは削除されて最新に上書き
- 記録として残るのは1分以上継続したチャプターのみ
- 誤タップ対策・スコアの精度向上

## 日付またぎ・時間軸仕様

**DBの保存方法**
- 分割なし・1レコードで保存
- startTime・endTimeをそのまま記録
- 日付またぎは許可する
- 実績チャプター同士の時間重複は原則禁止する

```swift
@Model
class Chapter {
    var startTime: Date  // 例: 2026-05-21 22:00
    var endTime: Date?   // 例: 2026-05-22 02:00
}
```

**スコア計算時**
- メモリ上で0:00仮想分割して処理
- DBには書き込まない

**タイムライン表示**
- 0:00-24:00 固定で表示
- ユーザーには分割を見せない

**重複チャプター**
- 通常のカテゴリ切り替えでは active Chapter を最大1件に保つ
- 手動追加・編集で既存実績と重なる場合は保存前に警告し、まずは保存をブロックする
- 自動で勝手にマージ・削除・切り詰めはしない
- 将来的に必要なら「重なった部分を置き換える」編集UXを追加検討する

**ランキング・比較**
- 全員0:00〜23:59の固定サイクルで統一

## 競合調査

**Toggl Track・ATracker・aTimeLogger（タイムトラッカー系）**
記録・グラフ・ウィジェットからの記録という設計は参考にした。ただし生産性・効率化を目的としていて記録が義務になりがちで続かない。ソーシャル要素がなく孤独でしんどい。予定との比較がないためスコア化できない。

**Zenly・whoo・Jagat（位置情報共有系）**
友達の存在を感じるという体験は参考にした。ただし位置情報の共有は監視感・束縛感が強く息苦しい。Zenlyはサービス終了していて位置情報共有への需要が落ちていることも判断材料にした。

**BeReal（SNS系）**
リアルな自分を晒すという設計思想と承認制フォローのゲーム性は参考にした。ただし記録が蓄積されず振り返りができない。プライバシー問題で若者の信頼を失っている。

**Duolingo（習慣化系）**
ゲーミフィケーションで習慣化するという設計思想・ストリーク・アンロック要素の設計は参考にした。ただし語学特化で汎用的な自己管理ツールではない。

## 差別化

**コアの差別化**
- 予定・記録・競争が一つの体験に統合されている唯一のアプリ
- 24時間まるごと記録する前提（自由時間・睡眠も含む）
- 位置情報ではなく行動ステータスの共有（監視感がない）
- 友達というフィルターが信頼性を担保する設計

**機能的な差別化**
- カテゴリ合計時間×時間軸の2軸スコア
- 過去・現在・未来が同じ時間軸で見えるタイムライン
- 行動ステータスの友達共有（既存アプリに存在しない）
- 累計スコアによるアンロック（1年で全解放 = 習慣化の完成）
- 複数人のタイムライン比較画像の書き出し
