# プロフィール装飾 — コード描画の品質再検証

2026-10-02 / **試作・採用未定**

## 何を比較したか

「葉隅」「星図線」のカードとフレームを2組制作した。新しい装飾本体は `NativeDecorations.swift` の SwiftUI Canvas / Path / Gradient で描画する。画像生成・既存画像のサンプリング・外部APIは使用しない。`renders/` のPNGは確認用の描画結果で、候補を描くための入力素材ではない。

既存画像は `decoration-masters` の該当4素材を比較シートの左列だけで使用する。左列は `ProfileComponents.swift` の配置・画像拡大・上方向オフセットを参考にした合成で、Liminalog本体のスクリーンショットではない。小サイズの比較は両列のリング中心線をアバター境界にそろえている。

今回は**同モチーフの再設計**。夜色の地・余白・細部の整理も変えているため、元画像の忠実再現や、描画方式だけの優劣を証明する比較には使えない。既存素材の明るい地に対する合成文字の読みにくさも、コード描画が優れている証明にはしない。

## 現時点の目視評価

| 対象 | 成立した点 | 残る課題 | 判断 |
|---|---|---|---|
| 葉隅カード | 葉脈・小花・枝の重なり、静かな文字面、カードとフレームの統一 | 葉の形の反復、角のクリップ、紙や絵具の細かな素材感 | 次の比較候補 |
| 葉隅フレーム | 24〜82ptで植物の輪郭が残る。葉・花・茎を別の形で描く | 元画像より密度と変化が少なく、細部が均質 | 採用保留 |
| 星図カード | 星座・軌道を周辺に置き、文字を読む余白を確保 | 原画の層状の光・空気感は未再現 | 次の比較候補 |
| 星図フレーム | リング位置、中心透過、星と軌道の配置を制御できる | 小サイズで線と点へ寄りやすい。画像の光や厚みを十分に置換できていない | 改善が必要 |

カードをコード描画する可能性は確認できた。フレームを含めた画像素材の全面置換は、この結果だけでは勧めない。審美的な合格・ユーザー承認は未取得。

## 今回の品質ゲート

技術検査と審美判断を分ける。以下はこの試作の検査条件で、全カタログの出荷規格を確定したものではない。

| ゲート | 方法・条件 | 結果 |
|---|---|---|
| 中心の透過 | フレーム中心から画像幅の30%の円内でalpha=0 | 両種・両解像度で合格 |
| 端の切れ | 画像外周4pxに非透明画素がない | 両種・両解像度で合格 |
| リング位置 | 主リング半径229/600。画像幅37.3〜39.0%の帯に360方向の有効画素がある | 360/360方向 |
| 画像寸法 | フレーム2048²・1024²、カード2048×1365 | 合格 |
| 文字面 | 通常サイズの本文列に相当する背景領域で、本文色 #D3DFE1 との最悪コントラスト4.5以上 | 葉隅9.23、星図線6.19 |
| 縮小 | 24 / 32 / 48 / 82ptのアバター、120×75ptのカードを目視 | 葉隅は形を識別できる。星図の存在感は課題 |
| 背景・文字拡大 | macOSの両背景シート、iOSのdark/normalとlight/accessibility1 | 各キャプチャで確認。全Dynamic Type段階の保証ではない |
| 欲しくなる品質 | 原画／実表示／組み合わせをユーザーが判断 | 未判定 |

検査の途中で葉隅カード右下の明るい葉が文字面の範囲へ入り、最悪コントラストが1.19となって失敗した。右下の植物群を縮小して文字面から外し、9.23まで改善した。目視の印象だけで合格にしないための実例として残す。

### センタリングに関する留意点

旧制作規格にある「alpha bbox中心±2px」を今回の出荷合格としては宣言しない。1024px出力で葉隅のbboxは(71,78)〜(946,952)、星図線は(71,82)〜(941,944)で、装飾の非対称性による偏りがある。主リングはコード上の中心に固定したが、bboxの許容幅を拡大して出荷規格を変更したわけではない。採用時に意図した非対称性として許容するか判断する。

### 未検証

- iPhone実機での見え方、実機Releaseの描画時間・スクロール負荷・メモリ。
- Liminalog本体の `ProfileHero`、コレクション一覧、友達画面への組み込み。
- 他カード／他フレームとの組み合わせ、全カタログの識別性、ランクごとの密度差。
- 元画像の筆致・光・素材感の忠実再現。
- accessibility1より大きい文字設定、全ての長い名前・自己紹介・写真。

カードの模様はサイズに応じて縦横に変形するため、極端な縦長カードでは植物の比率にも影響する。採用検討時は角の装飾を固定比率で配置する方式へ進める余地がある。

## ファイルと再現

- `NativeDecorations.swift`: 画像を参照しない装飾本体。アプリのターゲットには未追加。
- `RenderStudy.swift`: macOS上で比較・確認用PNGを書き出す。
- `PreviewApp.swift`: iOSの独立したプレビュー。`--light` / `--large` / `--celestial-first` で起動条件を指定。
- `validate_renders.py`: PNG寸法・透過・リング位置・本文背景の検査。Python + Pillowが必要。
- `render.sh`: macOS書き出しと検査。
- `build-simulator.sh` / `PreviewInfo.plist`: シミュレータ用のビルド。インストールや起動は自動実行しない。

実行環境はXcodeのSwift 6.4、iPhoneSimulator 27.0 SDK。iOS 27.0シミュレータで起動を確認した。コンパイラがsysroot名の警告を出すため、他のSDKへの互換性は別途確認が必要。

```sh
zsh design/profile-rendering-study-20261002/render.sh
zsh design/profile-rendering-study-20261002/build-simulator.sh
```

今回追加した内容はこの実験ディレクトリ内のみ。既存のProfileComponents / ProfileDecorations、画像マスター、Assets、ID、解放条件、課金、プロフィールの設計方針は変更していない。
