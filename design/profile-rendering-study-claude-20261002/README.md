# プロフィール装飾 — コード描画の再検証（Claude試作）

2026-10-02 / **試作・採用未定**

画像生成へ移行したプロフィールカード／アバターフレームを、現在のモデルでコード描画したらどこまで届くかを確かめるための限定的な試作です。
画像路線の決定（docs/23 §0）、本体コード、画像マスター、Assets、カタログ、ID、解放条件、課金、設計方針はどれも変更していません。追加したのはこのフォルダだけです。

## 先に結論

| 対象 | 判断 | 理由 |
|---|---|---|
| **カード（葉隅・星図線）** | **有望** | 文字面・縁・角の構造は画像より正確に制御できる。カードの高さに合わせて描き直せるため、大きな文字で高さが伸びても縁と文字がぶつからない。弱点は筆致で、葉の水彩の厚みは「水彩風の上質なイラスト」止まり。 |
| **フレーム（葉隅）** | **条件付きで有望** | 実際の表示サイズ（24〜82pt）では既存PNGより形が読める。一方、原寸で拡大すると、ドライフラワーのような繊細さと暖かさでは画像が上。カードとの統一のため色も変えている。 |
| **フレーム（星図線）** | **意匠を変えれば成立／原画の再現としては未達** | 「夜空の帯＋金の軌道＋星座」に組み直し、小さな表示でも存在感を出した。ただし原画の煙と金粉のような繊細さは置き換えられていない。拡大すると「紫の水彩の輪」に寄って見え、やや重い。 |

審美的な合否とユーザーの承認は、どれもまだ得ていません。数値検査に通ったことは「事故がない」ことを示すだけです。

## 何をどう描いたか

装飾本体は SwiftUI の `Canvas` / `Path` / グラデーションだけで描いています。画像生成、既存PNGのサンプリングや貼り込み、外部APIは使っていません。既存PNGは比較の列にだけ表示しています。

### 共通の部品（カードとフレームで同じものを使う）

- **植物**：葉は4種類（披針形・卵形・丸葉・柳葉）。1本の枝の中では種類を揃え、枝ごとに変えています。葉ごとに長さ・幅・反り・左右非対称・最大幅の位置・葉先の尖りが変わります。描き方は、付け根から先へのグラデーション、片側の陰、縁の顔料溜まり（3段の内側ストローク）、主脈と側脈です。14%の葉は葉裏の色にしています。小花は5弁で、花弁ごとに角度と長さを揺らし、傾けて楕円に潰すことで向きの変化を出しています。花の下に薄い影を落とし、葉や蔓の上に載っているように見せています。ほかに蕾と萼、ラベンダーの実、レースフラワー、かすみ草のような房があります。
- **星図**：手で設計した5つの星座形をカードとフレームで共有しています。星は「小さな白い核＋細く長い光芒＋核の数倍に留めた暈」で、円盤を大きくしていません（ボタンのように見えるため）。ほかに丸で囲んだ星、目盛り付きの軌道弧、加算合成の光の筋と星屑があります。

### フレーム

- **アバターとの位置合わせ**：本体の `ProfileIconFrameView(size:)` と同じ `size` を受け取り、`size × 1.12` の正方形に描きます。1024pxマスターのアバター半径383pxを1単位として、リングの中心線をアバターの境界に合わせています（既存PNGと同じジオメトリなので、そのまま差し替えて比較できます）。
- **葉隅**：同じ周波数で位相をずらした6〜8本の蔓が互いに潜り合います。奥の区間は暗く細く、手前は明るく、芯にハイライトを入れています。小枝は古典的なリースの構造で、下から左右に分かれて上で出会います。輪に寝かせるように伸ばし、外周1.28／内周0.90単位に収まるまで自動で長さを縮めます。茂みの山はカードの角と同じ対角（左上寄り・右下寄り）に置き、同じ一点から扇状に開く花束にしています。
- **星図線**：帯の内側（アバター側）は濃紺で、外側へ向かって菫色の星雲として抜けます。濃紺にしたのは、紫のアバターに帯が溶けて輪郭が膨らんで見えたためです。その上に筋雲とダストレーン（帯の形で切り抜き）、途切れた金の内縁線、傾いた楕円軌道、目盛り弧、弦、星座、帯からはみ出す一等星4つを重ねています。
- **小さい表示への対応（LOD）**：実ピクセル密度から詳細度（0〜1）を計算し、24〜32ptでは要素を減らして大きくします。線は最小0.85〜1px、細部（かすみ草・目盛り・星屑の大半）は省きます。

### カード

- 渡された矩形にそのまま描くため、`scaledToFill` やオフセットの補正は要りません。縁から最大12pt（基準サイズの場合）はみ出せる余白を持たせています。本体の画像も1.08倍で枠の外へはみ出しているので、それと同程度です。
- **葉隅**：紙の断面、水彩のにじみ、紙の粒、内側の縁のにじみ、二重罫、頂部・底部の飾り（葉2枚としずく）を描きます。にじみは円ではなく不規則な形にし、乾き際を残してから軽くぼかしています（完全な円は「コードっぽさ」が出たため）。角の茂みは、左上を小さく（アバターと競わないため）、右下を主役にしています。右下は本文側へ伸びすぎないよう、空いている下辺側へ多く流しています。
- **星図線**：ラベンダーの夜空、フレームと同じ星雲の煙（角だけ）、点線と目盛りの同心軌道、二重罫、星の飾り、星座、細い光芒。本文の下は明るく保っています。

## 数値検査（`validate.py`）

| フレーム（1024px） | 中心の透過半径 | 外周4pxの非透明画素 | bbox中心のずれ | 360°の途切れ | 帯（0.88〜1.12）の平均α |
|---|---|---|---|---|---|
| 既存PNG 葉隅 | 0.74 | 0 | (0, −1) | 360/360 | 0.37 |
| コード 葉隅 | **0.90** | 0 | **(−11, 0)** | 360/360 | 0.43 |
| 既存PNG 星図線 | 0.71 | 0 | (−0.5, 0.5) | 360/360 | 0.22 |
| コード 星図線 | **0.85** | 0 | **(5.5, −9)** | 360/360 | 0.66 |

- 中心の透過半径はアバター半径を1とした値です。コード版は既存PNGよりアバターの内側へ入り込まず、顔を隠す量が少なくなっています。
- bbox中心のずれは、旧制作規格「±2px」を**満たしていません**。リングそのものは構造上ちょうど中心にあり、ずれは意図した非対称（対角の茂み・一等星）によるものです。82pt表示に換算すると約1.2ptです。許容するかは判断が必要です。

| カード（350×226・@3x、本文列） | 背景輝度の平均 | ばらつき（SD） | 差分合成文字のコントラスト 5パーセンタイル |
|---|---|---|---|
| 既存PNG 葉隅 | 0.73 | 0.068 | 8.0 |
| コード 葉隅 | 0.79 | **0.042** | **12.0** |
| 既存PNG 星図線 | 0.55 | 0.064 | 3.7 |
| コード 星図線 | 0.62 | 0.065 | **4.5**（4.46。AAの4.5にわずかに届かない） |

- 本体の文字は「白＋差分合成」です。中間調の背景では文字も中間調になりコントラストが落ちるため、星図カードは本文の下を明るくして 2.9 → 4.46 に改善しました（最初の版は既存PNGより悪化していました）。
- 最小値（葉隅で約1.0）は、本文列の矩形の角に葉先が数px入ることによるものです。既存PNGも同じです。

**描画時間の目安**：macOS（Apple Silicon）の `ImageRenderer` で計測した1回あたりの時間です。実機の値ではありません。

| 描画 | 時間 |
|---|---|
| 葉隅フレーム 82pt@3x | 9.2ms |
| 葉隅フレーム 32pt | 1.8ms |
| 葉隅カード 350pt | 5.5ms |
| 星図線フレーム 82pt | 1.1ms |
| 星図線カード 350pt | 2.3ms |
| 参考：PNGフレーム表示 | 0.8ms |

葉隅フレームは蔓を線分ごとに描いているため重めです。採用する場合は、表示サイズごとに一度ラスタライズしてキャッシュする前提になります。

## 残った課題（そのまま書きます）

1. **筆致の差**：原寸で拡大すると、既存PNGの「描いた葉」（透ける重なり、ムラ、繊細な葉脈）に比べて、コードの葉は形の整ったイラストに見えます。228×142の詳細プレビューやギャラリーの大きなフレーム（164〜176pt）では、この差がはっきり出ます。
2. **葉隅フレームの色**：カードとの統一のため、エメラルド・ラベンダー・クリームに寄せました。既存PNGの暖かいドライフラワーの魅力は再現していません。枝の構造にも反復感が少し残り、巻きひげはやや機械的です。
3. **星図線フレームの重さ**：小さい表示で存在感を出すために帯を濃くしたので、拡大すると「報酬感」より「太い輪」に寄ります。docs/16 の「控えめな報酬感」との兼ね合いは目視での判断が必要です。
4. **大きな文字（AX1）**：本文の最終行が右下の装飾（葉・星）にかかります。読めますが、重なってはいます。既存PNGも同じで、PNGのほうは枠線が文字の上を通ります。
5. **一覧の小さなカード（120pt）**：葉隅の角の茂みは、既存PNGより控えめで寂しく見えます。
6. **試したアバター色**：紫の1色と、写真相当のコード描画1枚だけです。本体ではアクセント色をユーザーが選べるため、ほかの色との相性は未確認です。
7. **未確認のこと**：実機、Release描画の負荷、本体への組み込み（`ProfileHero`・友達画面・コレクション）、他の装飾との組み合わせ、AX1より大きい文字、`.plusLighter` やぼかしレイヤーの描画の端末差。

## Codex先行試作との比較（`compare-3way-*.png`）

自分の試作を作り終えてから比較しました。Codex側のファイルは変更せず、読み取り専用でコンパイルに含めて、同じ擬似UI・同じ縮尺で並べています。

- **Codex**：カードの地を夜色（深緑・紺）に組み直し、装飾を間引いた静かな設計です。文字は明るく、コントラストが高く出ます。docs/16 の北極星「暗めの余白」には、こちらのほうが近い面があります。一方、フレームは細い輪に寄り、星図線は24〜48ptでほぼ線と点になります（Codexの README にも課題として書かれています）。
- **Claude（この試作）**：既存PNGの色と豊かさ（明るいミント・ラベンダー、角の茂み、星座）を保ったまま、コードに置き換える方向です。フレームは小さいサイズでの存在感を優先しました。その分、拡大時にはやや重く、明るい地なので文字は差分合成に頼ります。
- どちらの方向を良しとするかは、色調の選択（既存PNGの明るい地を守るか、夜色に寄せるか）でもあります。描画方式の優劣だけでは決まりません。
