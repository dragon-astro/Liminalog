# カレンダー上部のプリセット入口

プリセット専用行がカレンダーを狭め、閉じる×の変更も不適切との指摘を受けた。後続の一段化も不採用となり、現在はこの上部配置に差し戻し、×は＋の右に復元した。[docs/35 §14](../../Liminalog/Views/Profile/docs/35-calendar-interaction-refinement.md)を参照。以下の画像では×の見た目と位置が現在とは異なる。

2026-09-29。月タイトルの下・曜日列の上に、予定プリセットと一日プリセットを一組で配置した。ドロワーを開いた後も入口が見え続け、そこから直接開ける。

ドロワーは通常サイズで一列。日付からまとめ、時間軸からタイムラインへ開く動作は維持し、＋を右端へ独立させた。大きな塗りつぶし円は使わず、閉じる操作は左端の下向き矢印にした。44ptの操作領域と元のドロワー高さを維持している。

日付選択済みならその日を引き継ぐ。未選択からタップする場合は、適用画面の「追加する日」で日付を確認・変更できる。ドラッグは置いた日を使う。適用後は対象日の一覧を開き、キャンセル時は元の表示を保つ。

画像はiPhone 17 / iOS 26.5 Simulatorの隔離fixtureで今回撮影した。保存先・日付変更・置換・ドラッグ・戻りの自動テストと、実画面の配置を確認している。操作時間や認知負荷の改善を測定した結果ではない。

SimulatorのUIテスト15項目と、通常Releaseのビルド・署名・fixture非包含の確認が成功。iPhone 16はCoreDeviceで「利用不可」のため、今回の実機への反映と指での操作確認は未実施。
