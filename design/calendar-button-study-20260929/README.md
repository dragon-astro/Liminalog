# カレンダーのボタン配置：情報設計と操作の比較

2026-09-29。配置の提案であり、採用仕様・実装指示ではない。アプリコードは変更していない。

## 前提

- 目的は「見やすく使いやすい」「見て気持ちいい」。ボタン数やタップ数だけを最小化しない。
- 中央の年月と左右2つずつの操作は、現状の基準とする。設定・表示切替・絞り込み・検索は常時見える入口を保つ。
- プリセット2つを直接押せる希望を優先する。入口を1つに統合する案は、この希望を緩める比較対象と明記する。
- ×は＋の右。ドロワーの通常ヘッダーは一列。Homeとアプリの既存タブを維持する。
- 長押しやジェスチャーはユーザーが挙げた可能性の例であり、採用決定ではない。

## 今回の観察

Device HubでiPhone 17 / iOS 26.5の隔離fixtureを操作し、同じSimulatorの画像を書き出して確認した。実データの多い月、6週ある月、実機の親指操作、VoiceOverの一連の操作は今回未確認。操作速度や好みの優劣は測定していない。

### 1. 月を眺める

![月表示](01-month.png)

上部は「左の2操作・中央の年月・右の2操作」というまとまりが明確。中央の日付が主役で、周辺のアイコンが同じ大きさ・色で揃っている。追加されたプリセット2つは独立した背景を持ち、見出しの下で左に偏った別のまとまりになっている。専用行には48ptを使う。画面を狭める対価として、この行の操作がどれだけ役立つかが課題。

### 2. 日付を選ぶ

![日付ドロワー](02-drawer.png)

日付・タイムライン・＋・×は一列。予定はカテゴリの色とアイコンで区別できる。プリセットは上部に残り、開く前後で入口が変わらない。一方、その日を開いて追加しようとすると、下部の＋と上部のプリセットに指の移動先が分かれる。

### 3. プリセットを開く

![プリセット一覧](03-preset.png)

予定名・色・時間を見ながら選べる。月へドラッグする操作は「型を選んで日付へ置く」という道具に近い。新規作成／予定プリセット／一日プリセットをすべて同じ場所に押し込むより、通常の追加と繰り返し使う材料の役割を分ける余地がある。今回は一覧を開くところまでを観察し、データの追加はしていない。

## 情報設計

| 役割 | 操作 | 見せ方の方針 |
| --- | --- | --- |
| カレンダーを把握・調整する | 設定、表示切替、年月、絞り込み、検索 | 見える位置と配置を安定させる |
| 選択した日を扱う | まとめ、タイムライン、追加、閉じる | 日付ドロワーの近くに置く |
| 作成に使う材料を選ぶ | 予定／一日プリセット、最近作った予定 | 相互にまとめ、タップとドラッグの両方を考える |

## 比較候補

| 方向 | 得られるもの | 負担・未解決点 | 評価 |
| --- | --- | --- | --- |
| プリセット2つを小さく浮かせる | 既存ヘッダー・2つの直接操作を保ち、上部の専用行をなくせる | 重なった予定を隠す。ドロワーとの距離や移動を慎重に設計する必要 | 最初に視覚比較する候補 |
| カテゴリからの作成もできる操作列 | タイムラインとの一貫性。月へ材料を置くための実用的な一段になる | カレンダーの高さは使う。カテゴリをタップ／ドラッグした結果を決める必要 | 高さに見合う価値があるか比較する候補 |
| ＋から作成方法を選ぶ | 初期画面は最も整理しやすい。作成の入口が一貫する | プリセットへ一手増える。以前の2つ直接操作の希望を緩める必要 | 比較対象、現時点の第一候補にはしない |
| 長押し・スワイプに入口を寄せる | 表示量を増やさず、慣れると短い操作にできる | 発見しにくく、既存の移動・作成・戻るジェスチャーと衝突しやすい | 唯一の入口にはしない |
| 既存ヘッダー内へ圧縮・その他へ集約 | 一段にできる | 年月の余裕と左右のまとまりを失う。常時使う操作が隠れる | 直近のユーザー評価から優先度を下げる |

### 浮かせる案で見るべきこと

日付未選択では画面下側、ドロワー表示中はその上端に沿う同じ2つの道具を想定する。ドロワーに隠れて消える配置にはしない。開閉に合わせた移動は同じ部品として連続させ、横位置やボタンの順序を変えない。プリセット一覧を開いた後に、背面の同じ道具を重複して強調しない。

ただし、操作列をなくしても、予定を覆ってしまえば見やすさは改善しない。6週ある月・予定名が詰まった月で、日付と予定を読めるか、タップやドラッグ先を塞がないかを確認する。空のカレンダー画像だけで採用を決めない。

### 内容のある一段で見るべきこと

単に空白を埋めるために要素を足さない。カテゴリを月の日付へドラッグして、そのカテゴリで作り始められるなど、月表示で頻繁に使う操作を担える場合に限る。カテゴリの選択状態が、フィルタなのか作成用なのかを見分けられる必要がある。

## ジェスチャーと見た目

通常タップの結果と整合するショートカットを優先する。プリセットをつかんで日付へ置く、表示切替ボタンから選択肢へ滑らせるなど、対象から結果を予測できる操作を候補とする。カレンダー全体への新しい横スワイプは月移動、ドロワー上端への縦操作は開閉と競合しやすい。長押しだけでしか到達できない主要機能は作らない。

[AppleのGestures](https://developer.apple.com/design/human-interface-guidelines/gestures/)は慣れたジェスチャーとの整合や、複雑なジェスチャーに対する簡単な代替操作を重視する。[Toolbars](https://developer.apple.com/design/human-interface-guidelines/toolbars)も関連する操作のグループ化と、追加メニューの発見しにくさを扱っている。これらは特定配置の正解を保証するものではなく、候補を評価する条件として使う。

見た目では、常時見える表面や背景の数、年月の左右の余裕、アイコンの線・濃さ、＋と×の距離、開閉中に部品が同じ位置関係を保つことを揃えて比較する。タップ領域は縮小せず、実機で片手の届きやすさを確認する。

## 次の比較
